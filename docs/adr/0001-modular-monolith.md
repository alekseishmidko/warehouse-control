# 0001. Модульный монолит в pnpm workspace

- Дата: 2026-10-17
- Статус: Accepted; выбор frontend частично заменён [ADR-0026](0026-solid-frontend.md).

## Контекст

Нужен учебный WMS с транзакционными складскими операциями и отдельными workers.

## Решение

NestJS/TypeScript, pnpm workspace, модули по бизнес-возможностям.
API и workers — отдельные процессы одного backend, одна PostgreSQL.
Исторический выбор 2026-10-17: React/Vite frontend после первого backend-сценария.
Текущий выбор frontend — Solid/Vite по [ADR-0026](0026-solid-frontend.md);
модульный монолит и pnpm workspace сохраняются.

## Альтернативы

Микросервисы усложняют атомарность до появления проверенных границ.
Неструктурированный монолит затрудняет владение остатками.

## Последствия и проверка

Проще транзакции и локальная отладка, но границы модулей нужно соблюдать явно.
Разделение deployment не означает независимые микросервисы.
Проверять отсутствие прямых записей в чужие таблицы. Этапы 1–2 roadmap.
