# 0018. Логин/пароль, серверные сессии и модель угроз

- Дата: 2026-10-29
- Статус: Accepted — только способ auth и threat assumptions; реализовано WMS-202, см. ADR-0020 и отчёт.
- Основание: явный ответ владельца продукта «согласен на Логин/пароль + серверная сессия,
  threat assumptions — согласен».
- Уточняет направление identity из ADR-0001 и будущую замену временного dev actor
  [ADR-0013](0013-http-idempotency.md). Транзакции/idempotency ADR-0013 не отменяет.

## Контекст

WMS-202 должна заменить локальную учебную identity настоящим входом и актуальными
правами. Frontend ещё не реализован; HTTP API и worker — отдельные процессы одного
модульного монолита, PostgreSQL — существующее хранилище. Нужен отзыв сессии и запрет
доступа по одному лишь знанию UUID склада/документа.

## Принятое решение и его границы

Вход по логину/паролю, состояние сессий на сервере в PostgreSQL. Не добавляем JWT
access/refresh, внешний identity provider или Redis только ради аутентификации.
Actor доверен лишь после серверной проверки личности/сессии; полномочия проверяются
backend на каждом запросе, включая idempotency replay.

Принята модель угроз T1–T9, подробно записанная в [identity](../identity.md): недоверенный
клиент и UI, подделка запроса, известные чужие UUID, подбор credentials, кража сессии,
CSRF, смена полномочий после входа, обязательный HTTPS для внешней сети и отсутствие
обещания защиты от полного захвата DB/host. Dev actor не может оставаться fallback,
обходящим production auth после её реализации.

Пароль хранится password hash; случайный session token не логируется, в БД планируется
его hash. Cookie/CSRF, параметры hashing и точная schema конкретизируются WMS-202.2/202.3.
Выбор не разрешает внешний deploy и не означает уже реализованную защиту.

Первоначальное подтверждение касалось только способа auth и threat assumptions.
Последующим ответом 2026-10-29 владелец продукта отдельно принял матрицу ролей/складов,
см. [ADR-0019](0019-warehouse-role-matrix.md); WMS-202.1 закрыта как согласование.
Absolute timeout 12 часов / idle 30 минут не утверждены и остаются предложением
в identity.md. Bootstrap, гранулярные admin permissions и точные API предстоит реализовать.

## Альтернативы

- Access/refresh tokens: отдельные правила отзыва и обновления, сейчас не выбраны.
- OIDC provider: полезен для будущего SSO, но не выбран для первого входа.
- Passkeys: не входят в текущий выбор логина/пароля.
- Продолжение dev actor: не выполняет требования аутентификации и складской изоляции.

## Последствия и проверка

Запросы зависят от доступности server-side session storage. Нужны безопасные credentials,
срок/отзыв и cookie/CSRF policy; endpoint без явно предоставленного доступа закрыт.
Принятый способ не даёт автоматически роль на всех складах. В WMS-202 runtime заменён на session auth/ACL без dev actor fallback (ADR-0020).

Матрица принята ADR-0019; реализация — WMS-202.2–202.6. Проверки: неверные credentials,
expired/revoked session, актуальные grants, 401/403, CSRF, чужой warehouse/document,
идемпотентный replay после отзыва доступа и отсутствие credentials/cookie/token в выводе.
Tests реализованы, результат — в отчёте WMS-202; подробный будущий flow и границы — [identity.md](../identity.md).

Текущий статус реализации и проверки: [WMS-202](../reports/wms-202.md),
[ADR-0020](0020-session-implementation.md). Числовые сроки всё ещё не утверждены как defaults.
