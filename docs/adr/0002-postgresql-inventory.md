# 0002. PostgreSQL, Drizzle и синхронный учёт остатков

- Дата: 2026-10-17
- Статус: Accepted

## Контекст

Конкурирующие операции не должны резервировать один и тот же товар сверх остатка.

## Решение

PostgreSQL — источник истины, Drizzle и явный SQL для транзакций/блокировок.
Только inventory меняет stock balances и reservations. Изменение, движения,
аудит и outbox — одна транзакция. Журнал движений append-only,
текущий остаток хранится явно. Полный Event Sourcing не вводим.

## Альтернативы

Асинхронное начисление/резервирование усложняет немедленный ответ и инварианты.
Полный Event Sourcing требует отдельного дизайна replay и версий всех состояний.
Другие ORM возможны, Drizzle выбран ради явной SQL-практики.

## Последствия и проверка

Нужны constraints, порядок блокировок и ограниченные retries транзакций.
Проверки на реальной PostgreSQL: последний товар, rollback и upsert новой строки.
Общая БД связывает выпуск модулей. Этапы 1–2.
