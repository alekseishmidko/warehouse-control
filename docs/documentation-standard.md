# Стандарт документации

Обязательные правила документации для разработчиков, менеджеров и агентов.
Документация обновляется в том же изменении, что и код, и входит в готовность задачи.

## Для кого пишем

Менеджер начинает с [продукта](product.md), roadmap и бизнес-раздела README модуля.
Разработчик читает архитектуру, технический раздел README, контракты и комментарии.
Оператор использует operations и runbooks. Агент читает AGENTS.md и эти же документы.

## Каждый модуль

У каждого backend-модуля, включая shared и infrastructure при их создании,
обязателен README по [шаблону](templates/module.md): назначение, роли, сценарии,
критерии приёмки, ответственность, данные, API, события, ошибки, транзакции,
конфигурация, файлы, проверки, эксплуатация, ограничения и статус реализации.
Неприменимые разделы объясняются, запланированное явно помечается.
До реализации бизнес-модулей их описание находится в architecture и product.

## Каждый файл

- Исходники, скрипты и тесты: file-level TSDoc/JSDoc или комментарий языка
  с назначением, местом в системе и существенными эффектами/ограничениями.
- Публичные классы и функции: контракт, неочевидные параметры, результат,
  ошибки, I/O, транзакционные требования и гарантии повторного вызова.
- Тесты: проверяемый инвариант, сценарий сбоя и нужное окружение.
- JSON и другие конфигурации без комментариев: назначение и значимые настройки
  в ближайшем README и [каталоге файлов](file-catalog.md). Не добавлять комментарии в JSON.
- Миграции: смысл изменения, constraints, совместимость и влияние на данные.
  Применённые миграции не редактируются ради комментариев.
- Документы: введение с назначением. Assets: происхождение и использование.
- Lockfile и generated code: генератор, команда регенерации, запрет ручного редактирования.
- Каждый собственный файл включается в каталог. Исключены зависимости, build output,
  IDE/cache, секреты и внутренние файлы Git.

Писать содержательно: назначение, причины и гарантии вместо комментария каждой строки.
Не дублировать TypeScript-типы в словах без объяснения смысла.
Общие правила описываются один раз: domain — инварианты, outbox — доставка,
contracts — форматы; README модулей ссылаются на них.

## Готовность изменения

1. Обновлены README модуля, file-level docs и file catalog.
2. Изменение поведения отражено в контрактах и бизнес-документации.
3. Описаны ошибки, конфигурация, миграции, примеры и проверки.
4. Команды существуют, ссылки рабочие, план отделён от реализации.
5. Проверено повторное использование по shared.md.

Пока это требования review. Автоматические CI gates полноты документации,
TSDoc и ссылок ещё не реализованы.
