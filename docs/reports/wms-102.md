# WMS-102: тестовая инфраструктура

Отчёт от 2026-10-18: все шесть шагов WMS-102 выполнены. Следующий этап работы —
WMS-103, прикладной transaction context и audit; они пока не реализованы.

## Реализация

Jest 30.5.2, Supertest 7.3.1, @testcontainers/postgresql 12.2.1,
@nestjs/testing 11.2.7; версии закреплены, требования сверены с npm metadata.
Тесты TypeScript компилируются tsc, Jest исполняет production dist через mapper.
Production source не получает Jest globals благодаря явным types.

Отдельный PostgreSQL 17.9-bookworm с тем же digest, что Compose, создаётся на suite.
Реальные SQL migrations применяются к новой случайно именованной БД.
Параллельные suites имеют разные containers/ports и не используют dev .env.
Fixture/reset вынесены в test/support, production бизнес-логика не скопирована.
Nest config внедряется через provider override без изменения process.env.

## Выполненные проверки

- pnpm test:unit: 24 проверки, Docker не требуется.
- pnpm test:integration: 3 suites, 8 проверок на реальной PostgreSQL.
- pnpm test: 4 suites, 32 проверки в двух Jest projects, maxWorkers=2.
- Проверены commit, rollback, SQL journal и очистка без удаления истории migrations.
- Supertest проверил /, /health и 404 настоящего AppModule; app pool закрывается.
- Намеренная assertion failure внутри resource scope не оставила pool/container;
  повторный dispose безопасен. Внешний тест проверяет исключение и успешный cleanup.
- Два живых harness одновременно записывают одинаковый key с разными значениями,
  очистка одной БД не меняет вторую.
- При запрете доступа к Docker socket отдельный integration-прогон завершился
  exit 1 с failed tests и нулём skipped — без ложного успешного результата.
- После успешного прогона контейнеров с label warehouse-controller.test=integration не осталось.
- Typecheck production source и tests прошёл.

Первый холодный запуск выявил default 5-second timeout Jest hooks: timeout в
project config оказался недостаточным для этой конфигурации Jest. Добавлен
setupFilesAfterEnv с jest.setTimeout(120000) и явные lifecycle hook timeouts.
Ryuk убрал остаточный контейнер первого неуспешного запуска; повторный и итоговый
прогоны завершились штатно, без forceExit. Это исправленный дефект первого прогона,
а не замаскированный пропуск тестов.

## Ограничения

Проверки metadata и HTTP — технический baseline, не доказательство надёжности
ещё не реализованного outbox. Testcontainers требует Docker/socket/registry.
При аварийном убийстве runner cleanup зависит также от Ryuk и daemon; timeout
cleanup считается ошибкой. Полный CI pipeline пока не настроен.
Native Compose restart smoke WMS-101 сохранён отдельно; config tests перенесены
в Jest без второй копии той же логики. Одновременные test:prepare в одном checkout
не поддерживаются из-за общего compiled output.
