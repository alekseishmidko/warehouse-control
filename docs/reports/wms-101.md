# WMS-101: окружение и первая миграция

Отчёт реализации и проверок от 2026-10-17. Все шесть шагов выполнены локально.
Следующая задача — WMS-102, изолированный integration harness.

## Проверенное окружение

| Компонент | Версия / ограничение |
|---|---|
| Host | macOS arm64, 18 GiB RAM |
| Node | 24.19.0 |
| Corepack / pnpm | 0.35.0 / 10.18.3 |
| Docker Desktop / Engine | 4.41.2 / 28.1.1, daemon linux arm64 |
| Compose | 2.35.1-desktop.1 |
| Docker VM | 11 CPU, 8217890816 bytes RAM, около 7.65 GiB |
| PostgreSQL | 17.9-bookworm, multi-arch digest в compose.yaml |
| drizzle-orm / drizzle-kit | 0.45.4 / 0.31.11, exact versions |
| pg / @types/pg | 8.23.1 / 8.23.1, exact versions; pg требует Node >=16 |

pnpm отдельно в PATH изначально отсутствовал; использован Corepack с временными
shims/store вне репозитория. Для обычной разработки — corepack enable.
Sandbox ограничивал socket Docker и сеть; проверки daemon/БД выполнялись
с разрешённым доступом. Порт 5433 занят другим проектом; WMS использует
только 127.0.0.1:15432. Чужие контейнеры не изменялись.

Выбрана фиксированная совместимая связка, а не плавающий latest.
Официальная документация подтверждает поддержку node-postgres в Drizzle и Pool.end.
Версии сверены с npm metadata, Docker image загружен и реально проверен на arm64.
Drizzle Kit имеет deprecated транзитивные esbuild-kit зависимости; это не блокирует
проверенную сборку, но полный security scan пока относится к последующим задачам.

## Результаты

- Compose поднят с пустым новым volume, healthcheck прошёл.
- Drizzle сгенерировал одну SQL migration и meta assets; schema — только metadata.
- Native config tests проверяют defaults, invalid input, redaction и startup failure.
- `test:db-baseline` применил миграцию дважды: в DB journal осталась одна запись.
- Временная запись сохранилась после restart postgres, затем была удалена.
- CLI миграции и проверки завершились в пределах timeout, pool не удерживает процесс.
- Build, typecheck и отдельная TS-проверка drizzle.config.ts прошли.
- HTTP `/` и `/health` проверены на API с реальной БД.
- После SIGTERM Nest корректно завершился; соединений с application_name
  warehouse-controller в pg_stat_activity не осталось.
- Повторная schema generation: no schema changes; frozen install прошёл.

На момент отчёта dev PostgreSQL запущен, named volume сохранён.
Остановка: `pnpm db:down`; удаление volume — отдельная destructive команда в Compose README.
Удаление данных в этой задаче не выполнялось.

## Границы результата

Складских модулей, outbox, auth, worker, API Dockerfile и Kubernetes ещё нет.
Health route не стал полноценной readiness probe. Dockerized PostgreSQL не означает
завершение dockerization backend. Локальная dev-роль не подходит для внешнего стенда.
Jest/Supertest/Testcontainers и транзакционная модель бизнес-сценариев — следующие задачи.
