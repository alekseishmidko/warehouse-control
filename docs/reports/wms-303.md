# WMS-303: внешний HTTP и TLS

## Изменение и требования до реализации

Application chart получил optional Gateway/HTTPRoute и отдельный web image/Deployment/
Service. `/api` сохраняется и идёт прямо в API; `/` обслуживает собранную SPA.
NGINX Gateway Fabric и Gateway API устанавливаются отдельно от application release.
Вход, доверие, предусловия, успешные/отказные ветки, сертификаты, commands и cleanup
подробно описаны у [владельца flow](../flows/gateway-tls.md).

Оператор задаёт hostname, HTTPS port, Secret reference и immutable image digest.
Client Host/Origin/forwarded headers не определяют actor/roles. Auth/CSRF/warehouse
policy остаётся в backend. Private keys и DB/session credentials не входят в Git,
rendered chart и web runtime. Root .env и рабочие dev volumes не менялись.

## Ревью, исправления и рефакторинг

1. Для SPA отсутствовал самостоятельный runtime. Добавлены минимальный static origin,
   multi-stage Dockerfile и optional Helm resources. Web не содержит proxy или DB credentials.
2. Проверка malformed path с `%00` сначала падала: filesystem отказ мог перейти в SPA
   fallback. Добавлено явное отклонение null/backslash; настоящий HTTP regression test
   проверяет confinement, API/assets404, malformed400, methods405, missing build503,
   MIME/cache и HEAD. Исходный отказ устранён, тест прошёл повторно.
3. `Programmed` появлялся до готовности data-plane Pod, port-forward завершался ошибкой.
   Gate теперь находит Deployment через selector Service и ждёт rollout до подключения.
4. Чистый PostgreSQL PVC выявил ложную readiness временного socket-only initdb server:
   следующий psql получал socket unavailable. Readiness проверяет TCP127.0.0.1; чистый
   повтор полного gate подтвердил startup, задержанную БД и restart/persistence.
5. Canonical digest/config identity после kind import вынесены в общий kind-image.cjs
   для backend и web; tag не подменяет digest. Отрицательные Helm tests закрепляют отказ
   без web upstream и с некорректным web digest; custom release проверяет имя Service.
6. Web image включён в существующий image-check через --web: clean no-cache inputs,
   canary scan всех финальных layers, image config и реальный read-only non-root
   ENTRYPOINT/HTTP/SIGTERM. Backend consumer сохраняет прежний entry point.
7. Повторное ревью охватило новые файлы, diff, Secrets, prefix precedence, release names,
   освобождение browser/port-forward/cluster и точность trust evidence. Системные hosts/
   CA trust не меняются автоматически. Статусы обновляются по реальному результату gate.

  Bundle проверен закреплённым SHA256. Remote kubectl kustomize ранее завершался
  сетевой ошибкой; это не скрытый fallback и не skip runtime tests.

к повтору исправленного полного сценария.

## Миграции, ограничения и эксплуатация

Новых SQL migrations нет. Hooks и runtime DB privileges WMS-302 сохранены. Gate
использует production seed/bootstrap owners только в отдельном admin fixture Pod;
нормальный runtime не получает migration Secret. Cleanup удаляет только свой cluster,
его PVC и временные credentials. Существующие кластеры/volumes не очищаются.

Node HTTPS проверяет доверенную цепочку и SAN без bypass. Chromium gate использует
ограниченное исключение для SPKI временного leaf, а не ОС trust store. Настройка и
удаление доверия dev CA обычным браузером документированы, автоматически не выполнялись.
Single-node тест не доказывает HA, production DNS/load balancer, mTLS, client-IP rate
limiting или active rollout. Startup/readiness/liveness и WMS-304 остаются отдельной задачей.
