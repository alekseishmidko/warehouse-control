# WMS-108: вертикальный сценарий приёмки

Отчёт реализации 2026-10-23. Сценарий работает в локальном dev/test режиме,
production identity и worker не входят в этот этап.

| Шаг | Результат |
|---|---|
| 108.1 | Receipts/lines, draft → posted, int4/1..1000/unique product, новые migrations 0009/0010, ADR-0014 |
| 108.2 | Draft проверяет товары, склад через ownership location/FK, kind receiving и лимиты; без stock/outbox |
| 108.3 | Parent FOR UPDATE, stock/movement/audit/outbox/status в общем context, productId lock order |
| 108.4 | Production create/post/get routes, DTO, normalized hash, atomic HTTP replay и regenerated OpenAPI |
| 108.5 | Реальные parent/unique lock waits, rollback winner takeover, SQL AFTER faults каждого существенного шага |
| 108.6 | HTTP request/response fixtures, выполняемый read-only SQL proof: 10 принято, одно движение/event, pending delivery, без task |

## Проверено

- `pnpm test`: **277 тестов**, 132 unit и 145 integration, 16 suites, PostgreSQL Testcontainers.
- Test prepare выполняет contracts:check, production build, OpenAPI diff и compilation tests.
- `pnpm typecheck`: production и test TypeScript.
- `pnpm db:generate` после новых snapshots: no schema changes; старые migrations не менялись.
- Новые migrations применены к пустым disposable БД всех integration suites.
- Все 20 новых собственных файлов включены в каталог; относительные ссылки и git diff --check корректны.
- После тестов контейнеров с label warehouse-controller.test=integration не осталось.
- Полный create/post через настоящие сервисы под `SET LOCAL ROLE warehouse_app` прошёл;
  права и SQL guards immutable истории проверены отдельно.
- Happy path выполняет [SQL из документации](../examples/receiving-result.sql),
  HTTP fixture проверяется actual class validator, response согласован с event fixture.

Fault injection в disposable БД: после INSERT header/lines/create audit;
при posting после balance, inventory audit, movement, receipt audit, aggregate counter,
event, stream, delivery, final status и saved HTTP result. Проверяются отсутствие
остатка/движений/нового аудита/всех outbox rows/неуспешного claim и сохранение draft.
После снятия fault тот же ключ успешно выполняет команду. Отдельно проверены два SKU,
ошибка после всех записей до commit, int4 overflow, forbidden refs/quantity/duplicates,
повтор с изменённым payload/target и отсутствие двойного эффекта при конкуренции.
Mocks для бизнес-результата не используются: barriers оборачивают реальный SQL,
fault triggers вызывают настоящие PostgreSQL ошибки. Прежний timeout/replay test WMS-107
остаётся в общем прогоне; receiving повторно использует тот же framework.

## Ограничения и следующий этап

Dev Compose не мигрировался/не перезапускался этой задачей: локально применить
`pnpm db:migrate` перед запуском. Native dev-volume restart smoke WMS-101 не запускался:
изменения проверены на disposable PostgreSQL без воздействия на рабочие данные.
Нет редактирования draft, отмены, компенсации, модели ожидаемой поставки и внешней
дедупликации поставок. Новый create key создаёт новый документ.
Production authentication/warehouse ACL, UI, performance/SLO, worker/putaway task,
Kafka, образ backend и Kubernetes ещё предстоят. Существующий dev actor только loopback opt-in.
SQL guards не защищают от DBA; соответствие всех stock/audit/event эффектов гарантирует
оркестрация сервисов и tests, не только constraints. Auto retry отсутствует.

Следующая задача WMS-109 — outbox worker; WMS-110 — handler размещения. Worker не должен
повторять начисление приёмки. [Контракт модуля](../../apps/backend/src/modules/receiving/README.md),
[демонстрация](../receiving.md), [ADR-0014](../adr/0014-receiving-vertical-slice.md).
