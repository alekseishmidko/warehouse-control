# WMS-402 — реализация, review и evidence

## Требования до реализации

Оператор включает отдельный локальный profile. Вход — безопасные operational JSONL,
spans WMS-401 и pull metrics. Correlation/event/trace IDs не задают права и не становятся
metric/index labels. Session/CSRF/warehouse ACL и AuditService сохраняются. Loki outage
не должен откатывать commit; внешние сообщения не разрешены. Все faults — в disposable
UUID projects, working .env/volumes не меняются. Storage limits предварительные, не HA/SLO.

## Review → исправления → повторное review

Проверены startup/lifecycle, зависимости shared/infrastructure, transaction boundaries,
SQL timeouts, bounded cardinality, Docker source permissions, metadata, collector retry,
retention, local-only receiver, compatibility стандартного app:up и изоляция тестов.

Исправления, закреплённые реальными проверками:

- Metrics snapshot не размножается при concurrent scrape: одна in-flight Promise;
  actual table lock доказывает server-side timeout и scrape_success0 вместо ложного backlog0.
- Метрики считаются до попытки sink, business success после commit buffer; отказ sink
  не отменяет receipt и не теряет metric counter. Raw errors/SQL/credentials не возвращаются.
- Metric keep-alive sockets unref: monitoring не удерживает отказавший startup после
  закрытия business resources. На SIGTERM/SIGINT metrics прекращают новые scrapes до pool shutdown.
- Ошибка worker до первого scrape не видна через increase одного counter: durable
  dead/retry дополняет handling-error alert. Первый fault gate воспроизвёл незажёгшийся alert.
- Loki auto service_name нарушал контракт4 index labels: discover_service_name отключён.
  Проверка использует series API, а не query-time labels после LogQL JSON parsing.
- У loki.source.docker собственный sync interval: default60s пропускал короткий CLI
  даже при discovery2s. Изолированный producer не находился до исправления, после source2s
  найден в Loki. Gate держит CLI wrapper до фактического collector acknowledgement, не sleep.
- CLI с network=container не имеет Docker IP/target: отдельный CLI network target и
  явный loopback TCP tunnel сохраняют local/admin guards, позволяют Alloy собирать реальные CLI logs.
- После Loki stop/start Docker port=0 может измениться: driver заново получает published
  port перед readiness/query, вместо обращения к старому адресу. Сам receipt при outage
  уже имел один movement/event/task/marker; timeout был дефектом адресации теста.
- Gate deadlines используют monotonic performance.now: jump wall clock при host/VM
  wake не обрывает readiness retry. Native regression с реальным HTTP503→200 и Date.now
  jump на сутки прошёл; business TTL/session/lease не менялись.
- Ошибка удаления CLI container больше не подавляется; cleanup failure проваливает gate.
- Tempfile credentials удаляются отдельным finally даже при отказе Docker cleanup.
- Receiver ограничивает не только число записей, но и alerts/record, label fields/value
  и request body. Native HTTP тест проверяет firing/resolved, границы и private field exclusion.
- Холодная install после изменения root package.json не помещалась в startup smoke
  timeout: настоящий pnpm docker:build выполнен отдельно до повторного fault gate.
  Тяжёлый coverage и fault gate далее выполняются последовательно из-за общих Docker VM ресурсов.

Ни applied migrations, ни generated contracts не менялись. Fault trigger существует
только внутри disposable БД и удаляется finally; stock/delivery recovery не сбрасывается SQL.

## Ограничения

Prometheus metrics — dev aggregation; большой backlog может timeout-ить snapshot.
Нет PostgreSQL server exporter, production HA, retention disk quota, backup/restore,
Kubernetes DaemonSet/RBAC deployment или внешнего доступа. В Compose namespace — project,
pod отсутствует. Docker socket ro не ограничивает API права: collector только доверенной
local machine. Для внешнего стенда нужны scoped permissions и authentication/network policy.

Логи могут потеряться/повториться при bounded retries, buffer fill, rotation, restart.
Нельзя обещать exactly once или полную историческую сохранность. Изоляция Loki outage
не означает изоляцию общего host/Docker disk/memory exhaustion. Receiver RAM journal
теряется при restart; это локальный проверяемый получатель, не incident archive.
Thresholds предварительные; SLO/baseline/recovery drill WMS-403/404 остаются отдельными задачами.
