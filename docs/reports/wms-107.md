## Проверено

- `pnpm test`: 242 теста (130 unit, 112 integration), 14 suites, реальные PostgreSQL Testcontainers и migrations.
- Build/compile tests, contracts:check и OpenAPI generation diff входят в test:prepare.
- `pnpm typecheck`: production/test TS.
- `pnpm openapi:generate`: offline без .env, DB initialization, Docker и HTTP listener; pool закрывается finally.
- DTO validation и dev actor config проверяются отдельно без Docker.
- `pnpm db:generate` после migrations: no schema changes; ранее применённые SQL не менялись.
- Контейнеры с label warehouse-controller.test=integration после прогона отсутствуют.
- Все 29 новых файлов включены в каталог, относительные ссылки и git diff --check корректны.

Новый HTTP controller существует только в test/support и регистрируется через harness;
production AppModule/OpenAPI его не импортируют. Он создаёт metadata, audit и outbox
для проверки реального общего commit/rollback. В production по-прежнему только `/`,
`/health`; GET `/api/v1/health` не появляется из-за prefix.

Проверены normalized replay без повторного callback, новый correlationId на replay,
один winner при concurrent equal requests и 409 при разных payload, rollback всех
таблиц, waiter после rollback первого, JSON null snapshot, разные actor/operation/target,
runtime grants и immutable saved response. Конкурентные commit/rollback сценарии
наблюдают настоящий unique lock через pg_stat_activity/pg_blocking_pids до освобождения
первой transaction, а не полагаются на случайный порядок HTTP. DTO неизвестные поля/строковые quantity,
invalid/missing key/correlation, malformed JSON, oversized JSON и proxy mode отклоняются.
Problem не содержит private driver/body/query values, для unknown errors — безопасный 500.

Timeout test использует постоянный loopback listener и настоящий клиентский deadline:
DB callback уже начался и заблокирован test gate, HTTP клиент получает timeout,
затем commit завершается; повтор исходного ключа возвращает сохранённый результат.
Supertest ephemeral listener не используется для этого сценария: abort закрывал бы
его во время retry и проверял гонку test server вместо протокола команды.

## Ограничения

Приёмка/HTTP business DTO/production authentication ещё не реализованы. Dev actor
выключен по умолчанию; запуск с ним в production/public bind запрещён config и guard.
Это защита локального учебного режима, не разграничение доступа между host-процессами.
Proxy и внешнее окружение требуют identity и отдельного этапа, не подмены actor header.

Хеширование не заменяет business normalization: controller включает нормализованные
body и target/path params. Auth проверяется до dedup на каждом запросе. Callback
не выполняется при replay, поэтому нельзя размещать только внутри него проверку
текущих прав доступа. HTTP idempotency не заменяет запрет повторного posting документа.

Сохраняются только успешные 200/201/202 JSON responses и relative Location. Произвольные
headers/cookies и non-JSON results запрещены. Ограничения JSON: depth 64, 256 КиБ;
key — UUID. Result body формирует доверенный сервис и не должен включать секреты.
БД должна быть доступна даже для replay. Автоматического retry, TTL/deletion и
consumer dedup нет; history растёт до отдельной retention policy. DBA способен обойти triggers.

OpenAPI UI/внешняя публикация, CI breaking-change comparison, frontend client generator,
worker redelivery/claim/recovery не реализованы и не проверялись этим этапом.
Native test:db-baseline не запускался: он перезапускает dev Compose и не нужен для
изолированных HTTP/idempotency tests. Dev volume/БД не мигрировались; выполнить
`pnpm db:migrate` явно при обновлении dev-среды. Следующая задача — WMS-108.
