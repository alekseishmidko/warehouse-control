# WMS-301: критерии и результаты

Владелец: [локальный kind и Helm](../flows/kind-helm.md). Этап создаёт локальную
учебную основу. Workloads, миграции и Gateway остаются задачами WMS-302/303.

## Границы до реализации

Вход: оператор выбирает локальный кластер, namespace, chart и dev values. Входные
values недоверенные; секреты и реальные данные в chart не включаются. Доступ к
кластеру определяется kubeconfig/RBAC оператора. Предусловия: Docker, kind, kubectl,
Helm и свободные ресурсы. Успех: отдельный cluster, локальный image, namespace и
Helm release; удаление release не означает удаления PostgreSQL данных. Ошибки команд
останавливают сценарий и не меняют чужие кластеры или volumes.

## Проверки и ревью

- Docker Desktop 28.1.1: 11 CPU / 8 217 890 816 bytes VM, host 11 CPU /
  19 327 352 832 bytes RAM; macOS arm64, около 51 GiB свободно на host.
- `kind version` — v0.30.0, binary во временном каталоге; `helm version --short` —
  v3.19.0; `kubectl version --client` — v1.32.2 из Docker.app. Существующая
  `/usr/local/bin/kubectl` — неработающая symlink; команды в PATH отсутствовали.
- `helm lint infra/helm/warehouse` и то же с `-f values-dev.yaml` — exit 0;
  `helm template wms ... -f values-dev.yaml` выдал один ConfigMap с profile dev.
  `--set profile=` отклонён required; SQL, credentials и workloads не генерируются.
- Ревью: chart не импортирует platform dependencies, не объявляет готовность WMS;
  values не содержат секретов. Kubernetes API не слушает пользовательский kubeconfig.
  PVC policy описана отдельно как план, не как проверенная реализация.

Полный `pnpm check:pr` не является проверкой Helm и в этой работе пока не выполнен.
Cluster/install/load и cleanup указаны ниже;
coverage backend/web в этом изменении не измерялось.

## Повторная проверка 2026-11-06

Исходная попытка с kind 0.30/Kubernetes 1.32 прервалась на загрузке node image.
После повторной загрузки с закреплённым digest успешно проверен поддерживаемый набор:
kind 0.33.0, Kubernetes 1.37.0, kubectl 1.37.0, Helm 3.22.0.
Kubeconfig находился в /tmp и не менял пользовательский context.

- `docker pull kindest/node:v1.37.0@sha256:a1ed56cfb0e7b93589bdf97c8cd566405a265939e3620fc4f5de89adff580ae5` — exit 0.
- `kind create cluster --name wms301-audit --image <закреплённый digest> --wait 180s` — exit 0, node Ready.
- `kind load docker-image warehouse-backend:local --name wms301-audit` — exit 0;
  запуск тестового Pod с imagePullPolicy Never дополнительно подтвердил наличие image.
- `kubectl ... create namespace warehouse-dev`, `helm lint`, `helm template`,
  `helm install warehouse ... --wait` и `helm uninstall warehouse` — exit 0.
  ConfigMap имел profile dev; после uninstall ConfigMap и Helm release отсутствовали.
- В отдельном PVC 1 GiB/RWO/standard синтетический файл сохранился после удаления
  и повторного создания Pod. StorageClass показал reclaimPolicy Delete; PostgreSQL,
  backup/restore и failure узла не проверялись.
- `kind delete cluster --name wms301-audit` — exit 0, `kind get clusters` пуст.
  Удалён только созданный кластер и его synthetic PVC; рабочие volumes не очищались.

AC-301-01/02/03/04/05 подтверждены перечисленными командами в рамках chart-основы.
После review исправлено расхождение версии Helm в runbook; повторные lint/template
прошли. Chart не запускает WMS; WMS-302–304 и gate 3 остаются невыполненными.
Backend/web source не менялся; `pnpm check:pr` не запускался, coverage не измерялось.
