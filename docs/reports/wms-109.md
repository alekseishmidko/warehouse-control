## Проверено

- `pnpm --filter @warehouse/backend test:prepare` затем
  `pnpm --filter @warehouse/backend exec jest --runInBand`: **309 tests, 19 suites**,
  144 unit и 165 integration; все выполнены успешно, Docker skip/fallback отсутствуют.
- Test prepare включает contracts generation check, production build, OpenAPI diff
  и compilation tests. API/schema events не изменились, ручного редактирования generated contracts нет.
- После усиления runtime allowlist ошибок отдельно повторён `pnpm test:unit`: 144 passed.
- После усиления race test наблюдением реального lock wait повторена worker integration suite: 17 passed.
- `pnpm typecheck`: source и test TS; `pnpm db:generate`: no schema changes после snapshots.
- Новые migrations применены к чистым disposable PostgreSQL 17 suites; старые SQL не менялись.
- Restricted warehouse_app обрабатывает marker/cursors с реальным audit эффектом;
  erase markers/rollback cursor запрещены DB grants/triggers.
- Все 22 новых собственных файла внесены в каталог; относительные ссылки и git diff --check корректны.
  После полного integration прогона disposable контейнеров не осталось.

Первый `pnpm test` с parallel suites получил временный timeout запуска PostgreSQL
в старой outbox suite (и связанный teardown failure), новый worker suite прошёл.
Проверены Docker health и отсутствие оставшихся containers; затронутые suites
повторены последовательно (55 passed), затем полный набор (309 passed).
Timeout не заменён skip/fallback и не скрыт увеличением лимита setup.

Fault injection AFTER SQL на effect, marker, consumer cursor, delivery completion и
transport cursor доказывает общий rollback. Проверяются race одного token, две worker
graphs с разными pools, SKIP LOCKED занятого потока, независимые агрегаты, marker
redelivery, live row locks после expiry, unknown schema, gap, transient budget и dead.
Child tests убивают реальный процесс до commit и после подтверждённого commit,
проверяют SIGTERM drain/deadline, отсутствие новых claims и висящих DB transactions.

## Ограничения

Dev Compose не мигрировался и не перезапускался: выполнить `pnpm db:migrate` локально.
Production handler ещё отсутствует: pending остаётся pending даже при `pnpm worker`;
фиктивного no-op нет. PutawayTask/stock effects WMS-110 не реализовывались.
Нет readiness HTTP, heartbeat, administrative inspect/retry/replay CLI, отдельной
quarantine table, retention deletion, Kubernetes, Kafka и централизованных логов.
Durable dead — остановленная delivery с безопасным code, не успешное подтверждение.
Handler только DB/awaited; CPU-blocking JS нельзя прервать event-loop timer.
DB timeout/deadline не заменяют SLA или performance tests. DBA может обойти guards.
At least once, порядок внутри destination/aggregate, без exactly once/global order.
