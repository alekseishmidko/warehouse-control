# WMS-112: Docker-упаковка первого сценария

Отчёт о фактически выполненных проверках 2026-10-28. Подробный сценарий и Mermaid —
[Docker flow](../flows/docker-gate.md), команды/переменные —
[Compose README](../../infra/compose/README.md). Внешний deploy/push не выполнялся.

## Результат для менеджера

Один image запускает API и worker отдельными процессами. При остановленном worker
приёмка 10 штук надёжно сохраняется; повтор posting с тем же ключом возвращает тот
же результат, новый ключ даёт 409. После запуска worker создаётся одно pending задание
размещения без дополнительного начисления. Рестарт БД/worker сохраняет результат.

## Проверенные команды

- `pnpm docker:build` — успешная сборка из рабочего checkout с allowlist context 1.26 MB.
- `pnpm docker:image-check` — успешная сборка из временных чистых inputs с --no-cache;
  host node_modules/dist не нужны. Fake secret в .env/.git/node_modules/dist/test
  отсутствует во всех layers экспортированного итогового image; image config не
  содержит DATABASE_URL/POSTGRES_PASSWORD/CONTAINER_DATABASE_URL. USER=node,
  ENTRYPOINT=[node], CMD=[dist/main.js]. Это targeted regression, не universal secret scan.
- `pnpm docker:gate` — PASS: временный проект/volume, реальные compiled processes,
  production default health через localhost published port, business 403 без dev actor,
  затем test-only loopback actor и настоящий create/post/replay/409.
- Gate: worker stopped → stock=10, reserved=0, movements=1, events=1, delivery=pending,
  tasks=0, markers=0; PostgreSQL restart и повтор миграции сохраняют snapshot/volume.
- Gate: worker started → stock=10, movement/event=1, delivery=completed, task/marker=1.
  Повтор posting и рестарт worker не меняют результат.
- Runtime uid=1000, PID 1 API `node dist/main.js`, worker `node dist/worker.js`;
  TypeScript/Jest/Nest CLI не resolve-ятся. Read-only rootfs/security options активны.
- `docker compose stop` SIGTERM: API exit=0, worker exit=0; graceful path прошёл,
  SIGKILL не потребовался. Script также допускает API=143 при re-raise SIGTERM.
- `pnpm test` — **23 suites / 363 tests passed**, unit и real PostgreSQL integration;
  prepare также выполнил contract generation diff, build, OpenAPI diff, test compilation.
  Это host suites, а не запуск Jest внутри runtime image.
- `pnpm typecheck` и `git diff --check` — успешно.

Проверенный image использует Node 24.22.1 bookworm-slim с закреплённым multi-arch digest,
pnpm 10.18.3, 132 production packages (полная build install 685). Compose использует
прежний закреплённый PostgreSQL 17.9. Host tests: Node 24.19.0. Контейнеры запускались на linux/arm64;
запуск/build под amd64 отдельно не проверялся.
После финального gate отсутствуют wms112-* containers/volumes; исходный dev
PostgreSQL по-прежнему healthy, uptime 10 days.
Gate cleanup удалил только свой созданный volume/project; dev БД не перезапускалась
и её volume не удалялся. Synthetic receipt UUID последнего успешного прогона
`2f70f339-ceb3-48c3-83f9-0993298eb629` служит evidence, данных после cleanup нет.

## Ограничения

Только локальный single-host Compose, без Kafka/Kubernetes/NGINX/production auth,
внешнего notification routing, image publishing/CI/signing/scanning. Обычный production
API разрешает только technical routes; gate actor включается отдельно внутри loopback.
Локальный DB owner используется и runtime, OS non-root не означает least-privilege SQL.
Migration service — startup gate; изменения migrations нужно пересобрать и применить
через app:migrate до запуска обновлённых процессов. Постоянная DB readiness не реализована,
GET /health по-прежнему process liveness, worker readiness probe отсутствует.

Контейнерный graceful test проверяет idle/poll; processing rollback/SIGKILL, два workers,
порядок, unknown contracts, stale token и recovery подтверждены существующими
[WMS-109](wms-109.md), [WMS-110](wms-110.md), [WMS-111](wms-111.md) integration tests,
прошедшими в общем прогоне. Отказ migration/startup ordering настроен Compose условиями;
отдельный failing migration container fault в этом этапе не вводился.
Физическое исполнение putaway остаётся будущей функциональностью. Следующий шаг —
WMS-201: уточнить правила складских операций до дальнейшей реализации.

## Дополнение: русские комментарии без изменения поведения

Dockerfile, .dockerignore, оба Compose overlay и оба проверочных скрипта получили
русские пояснения назначения, доверия аргументам/среде, стадий сборки, pnpm symlinks,
startup dependencies, liveness, PID 1/SIGTERM, временной изоляции и cleanup.
В image-check объяснён перенос хвоста между chunks при поиске canary, в gate —
параметризация SQL, HTTP replay/409 и отличие committed результата от вывода логов.
Срок polling проверяется между чтениями; уже начатый Docker-вызов ограничивается своим timeout.

[Карта комментариев](../flows/docker-gate.md#карта-комментариев-wms-112) связывает файлы с флоу.
Русский язык пояснений закреплён в AGENTS.md и стандарте документации; идентификаторы,
флаги и машинные коды сохранены. Правки затрагивают только комментарии и документацию:
проверка TS/CJS без комментариев, Docker/Compose инструкций и checksum SQL/JSON подтвердила
отсутствие изменений исполняемого/generated содержимого. Дополнительно прошли typecheck,
168 unit tests, build и generation diffs; Docker gate/image-check и integration повторно
не запускались. Их фактические результаты до дополнения приведены выше.
