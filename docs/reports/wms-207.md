# WMS-207: чтение и история

## Реализация

Восемь warehouse-scoped GET списков: stock/available, movements, receipts, orders,
putaway, picking, shipments, audit. Read DTO и query DTO отдельные, repositories
остаются у владельцев. Общий keyset adapter и cursor protocol переиспользуются.
Полный [флоу, Mermaid, примеры и ограничения](../flows/warehouse-reads.md).

Новая migration 0032 содержит только 11 индексов. Applied migrations не менялись.
Рабочая локальная БД не мигрировалась этим заданием: применение подтверждается
реальными migrations внутри каждой disposable integration suite.

## Набор для планов

Тест создаёт данные через production владельцев, без SQL правки stock:
четыре склада, два набора по 400 SKU/posted lines, 100 дополнительных резервов/
планов сборки с явной отменой, 500 draft приёмок и 500 draft отгрузок.
Тест исполняет ANALYZE, перехватывает SQL реальных repositories без подмены
результата и запускает EXPLAIN ANALYZE BUFFERS FORMAT JSON для всех восьми запросов.
Затем полностью обходит страницы stock/movements/putaway/orders/receipts/picking/shipments.

Первый локальный прогон: stock/movements/putaway/receipts/orders — индексные планы
без sort; picking и shipments — top-N heapsort после join orders; audit — обратный
scan audit_time_page_idx и scope subplans. Все планы вернули 21 строку для limit=20.
Это небольшой учебный набор с несколькими складами и связанными данными, не
нагрузочное испытание и не подтверждённый SLO. Конкретный выбор плана зависит от
статистики и количества данных. Проверка не отключает Seq Scan и не форсирует индекс.

## Ревью и исправления

Первое ревью выявило граничный случай cursor: год 0000 допустим для JS Date, но
недопустим для PostgreSQL timestamptz. Без дополнительной проверки forged cursor
мог дойти до SQL вместо 400. Добавлены отказ до SQL, unit и HTTP regression.

Уточнено значение available: арифметически свободный stock не разрешает reserve
в receiving/shipping. Balance DTO получил locationKind; фильтр зоны и комментарии
согласованы с inventory owner. Проверена связь cursor с этим новым фильтром.

Повторное ревью проверило SQL parameterization, scope всех полиморфных объектов,
точность ключа, no-store, принадлежность repositories, worker graph без auth,
актуальность OpenAPI/README и отсутствие изменений прежних миграций.

## Ограничения

Нет server-side snapshot между страницами, count/total, свободного поиска,
произвольного sort, глобального audit/identity view или read-model projection.
Audit changes намеренно не выдаются. Отдельного detail endpoint одного audit entry
нет: его metadata доступны через фильтры entity/correlation. Existing detail API
складских документов и заданий сохранены. DBA не ограничивается runtime политикой.
Frontend, Kafka, Kubernetes и внешнее развёртывание не проверялись.

## Команды

Полный gate перед PR: `pnpm check:pr`, Docker обязателен. Локальная команда всех
функциональных проверок — `pnpm test:functional`. Отдельный focused прогон после
`test:prepare`: `pnpm --filter @warehouse/backend exec jest --runInBand --runTestsByPath .test-dist/test/integration/warehouse-reads.spec.js .test-dist/test/integration/warehouse-read-plans.spec.js .test-dist/test/unit/keyset-page.spec.js`.
Итоговый `pnpm check:pr` завершился с exit code 0: **571 tests / 37 suites**,
Jest 110.162 s. Пройдены Prettier, TypeScript backend/tests, production build,
event generation diff, OpenAPI generation diff и обе Jest projects с настоящими
PostgreSQL Testcontainers. Добавленные 33 tests входят в этот прогон.
Повторное ревью после исправлений не выявило новых подтверждённых дефектов
в изменённом коде; границы оценки перечислены в разделе ограничений.

Проверка SQL-планов запускалась также отдельно до полного gate. Временные БД и
контейнеры освобождены harness. Проверены `git diff --check`, локальные ссылки и
наличие новых собственных файлов в file-catalog. Процент code/branch coverage
этим отчётом не заявляется. `pnpm test:functional` отдельно не повторялся: полный
gate уже выполнил те же integration suites. Docker image build/gate не менялись
и не запускались для read-only изменения.
