# WMS-503: Outbox publisher

Статус: **WMS-503.1–503.6 выполнены и проверены**. Прежняя блокировка диска
снята; Docker/Helm/Strimzi gates и финальный check:pr завершились с exit0.
Последний результат после дополнительного ревью:659backend tests/50suites,54web tests,21publisher scenarios.

## Контракт и границы до реализации

Участник — оператор локального dev-стенда с runtime PostgreSQL login и mTLS Kafka
principal. Триггер — явный запуск отдельного publisher. Публичного HTTP endpoint
публикации нет. Вход — retained immutable outbox; даже этот вход проверяется по
JSON Schema и SQL identity до сетевой отправки. Actor/warehouse ACL остаются у
бизнес-команды; transport не создаёт складской эффект.

Бизнес-writer, envelope/eventId и прежние inventory.putaway deliveries не меняются.
Новый destination kafka.publish создаётся лениво для следующей версии retained stream
с cursor0. Требуются PUBLISHER_ENABLED=true и PUBLISHER_REPLAY=from-start. Отсутствующая
история блокирует startup. Consumer effect/markers, cutover, HA, external deployment
и рабочая БД не входят в эту задачу.

Успех — broker transaction commit ack, затем один PostgreSQL commit для completed и
cursor. При uncertain ack/crash eventId сохраняется, duplicate допустим, потеря через
ложный completed запрещена. Dead блокирует свой stream. Network I/O не входит в SQL
transaction. [ADR-0034](../adr/0034-outbox-kafka-publisher.md),
[подробные шаги, Mermaid, конфигурация и recovery](../flows/publisher.md).

## Review → исправления → повторное review

Проверены новые файлы, diff и связанные writer/schema/migrations, worker claim filter,
logging, Registry/AsyncAPI generator, Docker build inputs, Helm и Kafka ACL пути.

Исправления по результатам собственного review:

1. Retry сначала не проверял число изменённых rows. Добавлены RETURNING и проверка
   обоих token owners; stale failure откатывает transaction. Regression test проверяет
   отсутствие cursor progress и неизменный processing после stale complete/fail.
2. Нельзя полагаться только на Deployment replicas1/lease. Добавлены session owner
   без reconnect и broker epoch; реальные session-loss/fencing tests подтверждают
   отказ старого owner и невидимость abort для read_committed.
3. Убрана тестовая plaintext ветка конфигурации: production и tests требуют mTLS.
   Фикстура использует подписанные ephemeral client/server certificates с hostname check.
4. Разделён service tick/validation и publishAndComplete; единый attempt budget;
   context logs получают correlationId после validation. Dead/retry имеют статические
   errorCode; SDK errors/payload/credentials не печатаются. Success только после SQL commit.
5. Topic mapping вынесен в один JSON source для Registry/AsyncAPI и generated runtime
   TS; дублирование mapping устранено. Writer/envelope не меняются.
6. KafkaJS2.2.4 создавал отрицательный timer delay на Node24 и печатал не-JSON warning.
   Узкий vendor patch clamps delay к0. Native regression и root process output проверяют
   отсутствие TimeoutNegativeWarning. Patch входит в frozen install; Docker ignore
   разрешает только этот конкретный новый файл. Image-check берёт полный список
   declared patches из package.json и проверяет production KafkaJS внутри image.
7. Новые3topics получили retention64MiB/partition, чтобы общий data budget вместе
   с receipt256MiB/partition составлял около1344MiB на dev PVC2GiB. Это не hard quota;
   internal logs/segments также занимают место. Нет обещания семи дней при byte limit.
8. Добавлен наблюдаемый барьер освобождения PG advisory lock после завершения child:
   сам exit процесса ещё не доказывает обработку TCP FIN PostgreSQL. Этот test-only refactor прошёл итоговый integration gate;
   дополнительного ожидания по случайному времени нет. Child crash barrier также получил bounded IPC wait и проверку exit до cleanup: отказ
   fixture не оставляет parent в бессрочном ожидании уже завершившегося child.

9. В ADR-0034 исправлена ссылка на исходное решение об outbox: ADR-0003, а не
   ADR-0006 о наблюдаемости/GitOps. Архитектурное решение не менялось.

Повторное review после исправлений не выявило новых подтверждённых дефектов в reviewed scope.
Это не утверждение об отсутствии всех уязвимостей проекта. Непроверенные сценарии
и ограничения перечислены ниже; Kafka consumer/cutover остаются отдельными этапами.

сбрасывается ручным SQL. HA publisher остаётся отдельной задачей.

## Пояснения по месту кода

По запросу подробное объяснение diff размещено рядом с Kafka producer settings,
вычислением topic/key/partition, claim/completion, session lock, shutdown, ACL и
retention, Registry preflight, generated mapping source и проверками SDK/Docker.
В service добавлена схема последовательности commit и окна duplicate.

JSON manifests/topology не допускают комментариев: поля объяснены в ближайших
README. Generated artifacts, migration0033 и vendor patch вручную не редактировались.
Пояснения patch размещены рядом с его regression test и в backend README.

Это изменение комментариев, не поведения. Проверены format:check, lint, typecheck,
schemas:check (exit0). Сопоставлены transpiled outputs14TS/CJS файлов с removeComments
и нормализацией whitespace, parsed Kafka YAML и Helm template без комментариев —
семантических изменений нет. Docker/Kind/full integration на комментариях не повторялись;
результаты659backend/54web выше относятся к последнему runtime изменению.
