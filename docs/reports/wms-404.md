по шаблону runbook. Идентификаторы disposable fixtures для этого отчёта не выдуманы.

## Ревью и ограничения

Первый DB fixture использовал stop/start с port=0: Docker сменил host port, поэтому
тот прогон отклонён. Refactor сохраняет endpoint: отключает LOGIN test role,
разрывает application connections и восстанавливает LOGIN удержанным admin client
в finally. Это реальный отказ доступа к БД, а не физический отказ диска/сервера.
Crash посреди транзакции проверяет отдельный worker test. Production fault flags,
stock SQL reset, новые роли, migrations и изменения lease/retry semantics не добавлены.

Повторное ревью: фиксированные paths тестов, private temporary raw Jest JSON,
публичные имена/status/duration; cleanup принадлежит существующему harness.
Согласованные dev-цели и границы описаны в runbook. Короткое sampled quiet window
не доказывает отсутствие шума за сутки. Availability/error budget, физический отказ
storage и длительный soak здесь не проверены.
