# WMS-401 — централизованное логирование и трассировка

## Требования и границы

Вход: HTTP correlation/trace headers, команда, событие outbox и результат доставки.
Headers/event extensions/errors не считаются доверенными. Право определяется прежней
session/CSRF/warehouse policy, не correlation/trace ID. Результат — безопасный JSONL
и связанные spans без изменения бизнес-эффектов, аудита, lease или протокола replay.
Ошибки sink/exporter не вызывают повтор складского эффекта. Нет внешнего deployment,
новой migration или изменения schemaVersion. WMS-402–404 не входят в этот отчёт.

## Реализация

Pino10.4.0/pino-pretty13.2.0 и совместимый OTel SDK0.301.1, resources/sdk-trace3.1.1,
API1.10.0 закреплены pnpm manifest/lockfile. Один экземпляр logger/SDK на процесс;
модули используют общие функции/ALS. Нет автоматического сбора SQL, URL, argv, hostname,
headers, payload или stack. Endpoint exporter — opt-in; без collector trace IDs работают.
Ни collector, ни dashboards WMS-402 здесь не устанавливаются.

Commit buffer выполняет I/O после db.transaction promise; rollback уничтожает queue.
Подтверждённый callback rollback отличается от неизвестного результата COMMIT/rollback
connection failure. Worker начинает новый root trace каждой попытки с producer link.
Те же eventId/aggregateId связывают HTTP → сохранённый envelope → retry/completed.
CLI stdout сохраняет протокол результата, operational JSON идёт только в stderr;
collector не должен собирать stdout inspect/bootstrap как логи приложения.

## Review → исправления → повторное review

Область: новые logging files и связанные entrypoints, HTTP/idempotency, SQL runner,
outbox writer, receiving, worker claim/process/failure, CLI/error paths и lifecycle.
Проверены архитектурные границы, совместимость события, отсутствие retries из-за логов,
commit timing, privacy, parallel ALS, startup ordering и ограниченное завершение.

Исправлены подтверждённые проблемы реализации с regression tests:

- Лишние identity fields/двойное module могли попасть в запись: явная проекция,
  child на том же sink и проверка сырой строки на единственное поле module.
- Успех callback не доказывает COMMIT: буфер до завершения runner; реальный deferred
  constraint fault проверяет SQL rollback, отсутствие receiving.posted/operation.completed.
- Ошибка COMMIT либо потеря ACK ROLLBACK не доказывает rollback: отдельное transaction.failed;
  pg_terminate_backend и barrier проверяют ветку без подмены SQL runner.
- Producer link сначала мог относиться к transaction child: worker передаёт root handler span
  явно; integration сравнивает точный producer spanId из durable envelope.
- NodeSDK с пустым набором processors не регистрировал tracing без collector: no-export
  processor сохраняет context; regression требует ненулевой W3C traceparent.
- SDK constructor учитывал OTEL_LOG_LEVEL и мог создать console diagnostics: constructor
  временно отключает этот канал, затем устанавливается safe static diagnostic adapter.
  Resource detectors/automatic metrics/log exporters отключены, env diagnostic не раскрывает raw errors.
- Recovery CLI прежний stderr parser ожидал один JSON object: parser проверяет **каждую**
  JSONL строку и выбирает error record; startup/stopped события больше не ломают CLI tests.
- Native Node.loadEnvFile и OTel exporter используют native process/dynamic imports:
  их контракт проверяется настоящими child executables; Jest mock не подменяет транспорт.
  Parent loader использует пустой файл, чтобы native env не протекал между suites;
  fault barrier отвергается при раннем завершении runner, cleanup не ждёт недостижимый сигнал.
- P2: idle PostgreSQL error наследовал ALS первого request, открывшего socket. Real
  pg_terminate_backend regression отказал до исправления (чужой correlationId в diagnostic).
  AsyncResource.bind связывает callback с startup owner pool; после исправления5/5
  observability tests прошли. Это также не даёт поздней ошибке попасть в закрытый log buffer.
- Fault cleanup сначала использовал общий harness pool: отдельный pool и barrier disconnect
  исключили выдачу убитого соединения cleanup. Ошибка теста не была объявлена успешным gate.

Повторное review исправлений выполнено. CLI Nest graphs также используют общий adapter:
framework сообщения идут в stderr и не смешиваются с результатом stdout. Ранее выключенный
Nest logger в bootstrap/seed/recovery заменён тем же adapter, что используют API/worker.
Окончательные результаты проверок и ограничения ниже.

## Ограничения

Operational logs/traces best effort; потеря stderr/exporter не откатывает warehouse commit.
При SIGKILL/жёстком process.exit flush не гарантирован. Отсутствие collector не является
ошибкой startup; spans без endpoint не сохраняются. Это не evidence Loki/Tempo установки.
CLI stdout — намеренный result protocol, включая payload только по явной inspect опции.
Его нельзя считать безопасным operational log sink. Privacy policy ограничивает содержание,
но доступ к логам стенда и retention определяются отдельно WMS-402.

Jest coverage и native child-process evidence различаются: ранний executable startup,
реальный pretty transport и OTLP exporter проверяются child tests, чьё покрытие не
сливается с parent Jest. Поэтому startup coverage не объявляется100%; весь backend
и все бизнес-ветки также не называются покрытыми на100%.
