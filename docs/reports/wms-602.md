→ merge → manual release/approval → GHCR → отдельный ARM64 kind. [Source task](../tasks/wms-602.json).

GitHub actor alekseishmidko имеет доступ к public repo alekseishmidko/warehouse-control.
Validation имеет contents:read. Publisher получает packages:write только после validation
и approval environment ghcr-release. Environment имеет required reviewer и main-only policy.
Verifier получает packages:read на новой ARM64 VM. Tokens передаются через stdin/private
Docker config/registry Secret, не через source/build args/layers/Pod mounts/артефакт.
Branch protection с required status checks отдельно не настроена; merge выполнен после
наблюдаемого успешного CI, без force-push. Environment approval допускает self-review.

## Scan policy и остаточный риск

| App     | LOW | MEDIUM | HIGH | CRITICAL | UNKNOWN | Waived UNKNOWN |
| ------- | --- | ------ | ---- | -------- | ------- | -------------- |
| backend | 13  | 49     | 0    | 0        | 4       | 4              |

Полный raw Trivy JSON остаётся в validation artifact. HIGH/CRITICAL, включая unfixed,
и неразобранные UNKNOWN блокируют gate. Шесть source rules до **2026-12-20 UTC** имеют
exact CVE/package/version/OS/base/Node/severity/status и требуют runtime proof;
FixedVersion, HIGH и expiry блокируют gate; новый consumer требует пересмотра исключения.
Две OpenSSL advisory могут иметь MEDIUM и тогда не используют UNKNOWN waiver.
[Причины и первичные источники](../../scripts/image-release/README.md).
Glibc gconv/glob и system libssl остаются в filesystem: это не исправление библиотек.
Вывод о недостижимости ограничен текущим JS-only приложением, Node ICU/JS glob,
отсутствием native addons/FFI/CLI и static Node OpenSSL3.5.9. Новые consumers/mounts требуют review.
ARM64 не защищает от libc glob CVE. Signing/SBOM, amd64/multiarch, GitOps и production
credential provisioning этим evidence не подтверждены.
