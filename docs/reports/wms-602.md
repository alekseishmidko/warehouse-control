# WMS-602: подготовка поставки образов

## Изменение и требования до реализации

Задание — WMS-602 из [плана](../development-plan.md). Пользователь подтвердил
GitHub Actions + GHCR для origin alekseishmidko/warehouse-control. Первоначальная
подготовка выполнена без публикации; новым поручением пользователь разрешил реальную
публикацию images и проверку pull. Отправка source commit в общую main требует
отдельного согласия после отказа automatic approval review. Deployment приложения не входит в это поручение.
[Source task](../tasks/wms-602.json), [flow](../flows/image-scan.md),
[команды и scanner policy](../../scripts/image-release/README.md).

Участник — локальный разработчик с Docker либо read-only Actions validator.
Вход — source snapshot, runtime images, Trivy executable и публичная vulnerability DB.
Tag — изменяемый указатель; scan экспортирует inspect ID, затем считает config digest
из реальных archive bytes. Успех — полный отчёт без HIGH/CRITICAL и без неразобранных UNKNOWN. Пользователь поручил обновить runtime и оформить только адресные обоснованные исключения.
Ошибка binary/DB/JSON или чужая идентичность запрещает passed. Складские данные,
HTTP/SQL/миграции, stock, audit/outbox не меняются; бизнес-AC транзакций здесь неприменимы.

## Review → исправления → повторное review

Область: новые YAML, scanner/связанные image gates, harness policy, scripts tests,
документация и статусы. Services/repositories/backend/web TypeScript source не изменяются; Dockerfiles и image gates обновлены.

1. Реальный первый scan воспроизвёл несовпадение Docker inspect ID и Trivy ImageID.
   Docker Desktop выдаёт OCI index; Trivy — config digest. `archiveConfigId` считает
   digest bytes из однозначного runtime manifest. Regression `image archive identity
uses config bytes and rejects ambiguous manifests` проверяет успех, traversal и ambiguity.
2. Review выявило возможность наследования TRIVY_* и checkout config. Добавлены
   `scannerEnvironment`, пустой отдельный config и regression overrides. Это выделение
   ответственности: config identity, JSON policy и process orchestration разделены.
3. Publish job отделён от candidate source: в нём нет checkout, dependency install
   или rebuild с packages:write. Credentials доступны только через env/password-stdin;
   DOCKER_CONFIG временный, logout/cleanup в EXIT trap. Permissions и action SHA
   закреплены regression реального YAML. PR из fork не запускает release.
4. Повторное review сохранило fail-closed policy и открытые внешние предпосылки.
   `ghcr-release` должен быть заранее настроен с required reviewers и default-branch
   restriction. Само имя environment в YAML **не создаёт protection rules**.
   Без внешнего подтверждения этих настроек запуск release не считается готовым.

pipeline используется уже доступный Node24.22.3. Tools размещены только в /tmp.

SHA-256 сверены. Рабочие .env/volumes не изменялись.

- `pnpm harness:plan docs/tasks/wms-602.json`: выполнено; окончательный plan/run
  и readiness читаются из artifacts/harness/wms-602/latest.json, не редактируются вручную.
- `pnpm test:pr-checks`: 9 tests, включая пять новых policy/archive/workflow tests.
  В sandbox прежний filesystem watcher test дал blocked вместо failed; вне sandbox
  та же команда прошла. Ожидания не ослаблялись.
- `pnpm check:docs`: passed до финального pipeline; повторяется внутри check:pr.
- `pnpm exec playwright install chromium`: exit0.
- Исторический `pnpm images:scan` до обновления runtime: реально выполнено после исправления config identity.
  Существующий backend image содержит LOW88/MEDIUM112/HIGH45/CRITICAL1/UNKNOWN12;
  gate дал nonzero. JSON: artifacts/image-scan/dd3c5bdc-e181-45df-8290-0a97089f152e/backend.json.

  отказа backend. Последующий harness проверяет новые builds, если предыдущие gates пройдут.
- Итоговый `pnpm harness:run docs/tasks/wms-602.json` запускает frozen install,
  полный `pnpm check:pr`, backend/web image checks, scan и Docker gate последовательно.

  текущего run не объявляется. Источник отчёта не переписывается после run ради freshness.

scan найденных уязвимостей не выдаётся за разрешение release. Пять адресных UNKNOWN exceptions описаны у владельца policy; неподтверждённые внешние AC остаются открытыми.

## Обновление runtime по поручению пользователя

AC WMS-602.RUNTIME: [ADR-0039](../adr/0039-minimal-node-runtime.md), оба Dockerfiles,
общий runtime.cjs, pure policy.cjs и source exceptions.json. Исходное правило WMS-602.3
сохраняет запрет HIGH/CRITICAL/unfixed; UNKNOWN допускаются только адресно по описанному
review. Применимость изменений сверена с прежним scan/test flow и entrypoints.

Вход: pinned official Node24.22.3 trixie-slim и distroless cc-debian13, production
lockfile/artifacts; participant — локальный Docker operator. Результат: прежние
API/worker/migrate/web с uid1000/Node PID1, без npm/Corepack/Yarn/shell/package manager.
Ошибка версии/base/runtime proof или malformed/expired exception запрещает release.
Рабочие .env, volumes, SQL, ACL и бизнес-правила не изменяются. Реальная публикация разрешена новым поручением; итоговое внешнее evidence сохраняется после выполнения.

### Review и рефакторинг

- Вместо удаления npm поверх Node base выбран чистый runtime base, где tooling
  отсутствует изначально. В нижних runtime layers тоже нет npm/Yarn/Corepack.
- Общий verifyRuntime переиспользуется image-check и scanner: immutable ID, pinned
  base/Node, uid1000, absence tooling/.node и shared libssl. JSON policy вынесена из
  orchestration; scanner сохраняет полный отчёт и counts, не фильтрует findings.
- Проверка prototype выявила gconv modules в filesystem. Поэтому они **не объявлены
  удалёнными**. Три glibc advisory исключены по недостижимости iconv через нынешний
  JS-only/ICU runtime, два libssl advisory — по отсутствию загрузки системного OpenSSL.
  Ограничения и первичные Debian sources находятся в [policy README](../../scripts/image-release/README.md#runtime-и-review-исключений).
- Повторное review усилило match: только OS/debian result, точные CVE/package/version/
  severity/status/OS/base/Node, отсутствие FixedVersion, runtime proof и срок до2026-12-20.
  Новая severity, новая версия/дата, native consumer или истёкшая policy не получают pass.
- Regression `runtime policy rejects unrelated expired and altered advisory exceptions`
  проверяет positive5 и негативные branch cases; старые generic UNKNOWN/HIGH/CRITICAL
  regressions сохранены. Полное удаление exception guard приводит к отказу этих проверок.

plan/run/ready — получить согласие на конкретный source push в main.

предложен отдельный local kind либо Docker Desktop. Выбор не считается согласованным
