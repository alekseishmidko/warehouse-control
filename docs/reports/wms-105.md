# WMS-105: контракты событий

Результат реализации 2026-10-21 для менеджера, разработчика и следующего агента.

## Что готово

| Шаг | Результат |
|---|---|
| 105.1 | Exact Ajv 8.20.0 + ajv-formats 3.0.1, draft 2020-12, strict/full formats без преобразования данных |
| 105.2 | Исходный ReceivingPosted example проверяется обеими runtime границами; UUID/UTC/quantity/required покрыты |
| 105.3 | Code registry type/version; prepareForOutbox и parseForHandler проверяют envelope/payload до возврата caller |
| 105.4 | Exact json-schema-to-typescript 16.0.0, генерация types/schema bundle, readonly generation diff gate |
| 105.5 | Отдельные полные fixtures optional fields, unknown version и invalid payload |
| 105.6 | 1..1000 строк, quantity int4, 256 КиБ JSON UTF-8; generated payload DTO/line limit, business docs |

Проверка принимает optional extensions, но отклоняет неизвестную версию отдельным
кодом. Producer получает независимый snapshot: дальнейшая мутация input его не
меняет. Runtime работает из dist без чтения docs/сети/БД.
Схемы и generated artifacts связаны командами, дублирования handwritten event DTO нет.
Общий технический код в shared/events не импортирует modules/infrastructure/Nest.

## Проверки

- `pnpm contracts:generate`, `pnpm contracts:check`: успешны; generated types и schema bundle воспроизводимы.
- `pnpm typecheck`: production source и test TypeScript без ошибок.
- `pnpm test:unit`: build и generation check включены; 113 тестов, 6 suites.
- `pnpm test:integration`: 56 тестов, 5 suites, реальные изолированные PostgreSQL Testcontainers и migrations.
- Production build выполнен test:prepare, без изменений DB schema/migrations.
- После integration нет контейнеров с project label `warehouse-controller.test=integration`.
- Проверены relative links изменённых Markdown и каталог всех 16 новых файлов; `git diff --check` без ошибок.

Контрактные тесты проверяют все required fields, UUID на всех уровнях, реальную дату,
UTC Z (offset даже +00:00 не допускается), int4 bounds без coercion, aggregateVersion,
optional metadata, 0/1000/1001 строк и точный предел UTF-8 bytes. Registry сверяется
с source schemas через generated bundle. Generation test обнаруживает missing/stale
types и schemas в temporary directory, не переписывая checkout, с finally cleanup.
Генератор запускается отдельным Node process из Jest: Prettier использует ESM import,
поэтому experimental VM flag для всего runner не нужен.

## Ограничения и следующий шаг

Outbox writer, действующий handler, consumer dedup/quarantine, HTTP DTO документов,
CI workflow, OpenAPI и breaking-change comparison ещё не реализованы. В WMS-105
проверены именно общие границы, а не SQL delivery protocol. В WMS-106 нужно обязательно
подключить prepareForOutbox до INSERT в существующем context, в WMS-109 —
parseForHandler до эффекта handler. Отказ не должен считаться успешной обработкой.

Максимальный размер producer проверяется после сериализации: это не защита памяти
от уже созданного огромного JS object. Transport должен ограничивать вход до decoding.
Generator не выражает все runtime constraints в TypeScript; новые schema keywords
проверяются на совместимость обоих инструментов. Семантические проверки документа,
дубликатов строк, справочников и прав остаются за receiving. traceparent только bounded,
OTel parsing не подключён. Ограничения добавлены до первой публикации draft v1.

Dev Compose не менялся, миграции не добавлялись и dev volume не перезапускался.
Native `test:db-baseline` не запускался: изменение не затрагивает dev Compose/storage.
Kafka и внешний Schema Registry не подключались. Следующая задача — WMS-106.
