# WMS-202: server sessions, роли и отсутствие dev actor

Реализация 2026-10-29. Принятые решения — ADR-0018/0019, технические — ADR-0020.
Подробный владелец исполнения/SQL/гонок: [identity flow](../flows/identity.md),
[модуль](../../apps/backend/src/modules/identity/README.md). Frontend/внешний deployment не добавлены.

## Что реализовано

- users, sessions (только digest browser token), warehouse_roles, auth_login_windows и
  one-time identity_bootstrap marker, новые migrations 0018/0019 и runtime/bootstrap grants.
- Стабильный Node scrypt N=2^17/r=8/p=1 с солью/ограничением work, точный bounded пароль.
- Login/me/logout, защищённые admin create/update/roles/revoke-all/revoke-one endpoints.
- Cookie/CSRF/origin policy, no-store и безопасные problem errors. Idempotency cache не
  принимает credential commands и не хранит быстрый fingerprint пароля.
- Warehouse policy для всех существующих receiving create/get/post, повторная проверка
  под locks до saved replay. Guard не создаёт actor из тела/заголовков, dev actor удалён.
- User/grants/session admin mutations и безопасный audit атомарны; роли/warehouse/flags
  отражены без hash/пароля. Последний active admin защищён даже при конкурентной блокировке.
- Одноразовый bootstrap через bounded stdin, opt-in/DB group/local scope/retained marker.
- DTO по файлам в dto/, пять таблиц по файлам в schemas/, русские описания полей/нюансов.
  Раскладка не меняет таблицы; Drizzle generation после разбиения — no schema changes.
- Root Prettier 3.9.10 с format/format:check; собственные исходники/документы отформатированы,
  SQL/generated/lockfile/.env исключены. Старые applied migrations не переписаны.

## Проверки

После разбиения DTO/таблиц и форматирования `pnpm typecheck` и полный `pnpm test` прошли:
**385 tests / 25 suites**, включая unit identity и real PostgreSQL/Testcontainers integration.
`test:prepare` также проверил generation diff событий/OpenAPI и production build.
Новые cases проверяют wrong/unknown/blocked credentials, expiry/idle/revoke, CSRF,
role A/viewer B, admin без warehouse role, replay после revoke, DB locks при смене grants,
last-admin race, SQL audit/session faults, bootstrap opt-in/role/one-time и login rate windows.
Дополнительный regression case проверяет expiry за время ожидания session lock:
clock validity читается новым SQL statement после получения lock, чтобы sliding touch не оживлял истёкшую session.

Финальный Docker gate после добавления Prettier и разбиения файлов прошёл: bootstrap/login/warehouse grant без bypass,
stock=10, movement/event=1; worker stopped → pending, task/marker=0; worker started →
completed, task/marker=1, stock прежний. PostgreSQL volume restart и Node PID 1/SIGTERM
прошли, API/worker exit=0, uid=1000. Receipt финального прогона:
`958d1488-a313-482d-86df-fea03a9828b2`. Данные disposable gate удалены cleanup.
Runtime-проверка подтвердила отсутствие Prettier и остальных dev dependencies.

`pnpm docker:image-check` проверил clean no-cache build, отсутствие canary в exported
final-image archive, отсутствие DB credentials в image Config и non-root exec entrypoint.
`pnpm format:check` и `git diff --check` также прошли.
Это targeted exclusion regression, не универсальный vulnerability/secret scanner.
`pnpm db:migrate` и `pnpm db:check` выполнены на локальном PostgreSQL 17.9: новые таблицы
созданы без удаления volume/складских данных. Root .env не переписывался, реальных
пользователей/default credentials не создавалось. Tests используют отдельные БД.

## Конфигурация и границы

Числовые 12h/30m не утверждены. Оба AUTH_SESSION_*_SECONDS обязательны явно, 30..86400,
idle<=absolute; `.env.example` оставляет пустые значения, API/bootstrap fail closed.
AUTH_ORIGIN обязателен, production HTTPS, dev/test HTTP loopback. Backend не TLS gateway:
внешнего stand не развёрнуто, HTTPS ingress/proxy policy предстоят. Docker gate использует
короткие собственные сроки и synthetic credentials в private stdin, не production defaults.

Пользовательские сессии могут истекать; stock reservations по B4 автоматически не истекают.
Отзыв ждёт уже допущенный callback и не отменяет committed warehouse факт. Worker/seed
не зависят от human HTTP auth. Локальный outbox admin CLI сохраняет отдельный DB/OS допуск,
не объявлен аутентификацией человека через HTTP. Оператор должен один раз создать первого
admin через bootstrap и назначить warehouse role перед ручными складскими запросами.

Нет MFA/SSO/password recovery UI, автоматического purge session/rate history, полноценного
DDoS/proxy real-IP решения, frontend или защиты от DB/host admin compromise. Отсутствующие
putaway/picking/shipping API не добавлены в OpenAPI как готовые. Следующая задача — WMS-203.

## Разделение сервисов внутри IdentityModule

2026-10-29: большой IdentityService заменён AuthService, SessionsService, UsersService и
AccessService. Внутренний IdentityTransactionsService переиспользует прежний bounded run,
user-profile.ts — единую безопасную проекцию. Repository и config остаются у identity;
отдельных Nest-модулей/процессов и циклических DI зависимостей нет.

AuthGuard, оба identity controllers, ReceivingController, bootstrap и test fixtures переведены
на соответствующих владельцев. SQL schema, HTTP paths/DTO, cookie/CSRF и матрица прав сохранены;
новых migrations и generation diff нет. requireSession возвращает безопасный профиль,
password hash остаётся внутри identity. Подробный sequence — [identity flow](../flows/identity.md).

После refactor `pnpm typecheck` и `pnpm test` прошли: **385 tests / 25 suites**.
Включены production build, OpenAPI/event generation diff и реальный compiled bootstrap.
Новый real PostgreSQL case `password update and delegated session revoke roll back together when audit fails`
вызывает AFTER INSERT fault на audit: прежний hash сохранён, две target sessions живы,
audit отсутствует. Существующие тесты подтверждают успешный reset, grants/replay и гонки.

Docker после разделения: `pnpm docker:build` и `pnpm docker:gate` прошли с актуальным image.
Receipt `85e2ac04-72a9-42ab-88f9-13ce36b761a9`: stock=10, movement/event=1;
worker stopped → delivery pending/task=0, worker started → completed/task/marker=1.
Bootstrap/login/warehouse grant, PostgreSQL restart, repeat migrations и SIGTERM прошли;
uid=1000, API/worker exit=0. Собственный disposable project/volume удалён cleanup.
`pnpm format:check` и `git diff --check` прошли; числовая auth policy остаётся явной,
без добавления defaults, внешний deployment не выполнялся.
