# WMS-501: Kafka infrastructure

## Границы до реализации

Вход: platform dev configuration. Участник — локальный оператор Kubernetes,
не внешний deployment. Outbox, stock, writer, migrations, business handlers не меняются.
Успех: собственный Strimzi cluster, mTLS publish/read и данные после restart broker.
Ошибки установки/готовности/проверок приводят к exit 1 и scoped cleanup.

| --------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| WMS-501.1 | infra/kafka/dev.yaml, scripts/kafka-gate.cjs                 | Пройдено: чистый kind, Kafka Ready, mTLS                  |

| WMS-501.4 | KafkaUser exact ACL, stable inventory.putaway group          | Пройдено: users Ready + реальный отказ write/чужой group  |
| WMS-501.5 | gate delete/recreate broker + read retained messages         | Пройдено: новый Pod UID и чтение прежних сообщений        |

Версии: Strimzi 1.3.1 / Kafka 4.3.2 / Kubernetes 1.37.0. Источники и процедуры —
[README](../../infra/kafka/README.md). Single broker/controller/RF1 не проверяет HA,
потерю node/disk, production backup или безопасный rolling availability.
Registry/publisher/application consumers/cutover не реализуются этим этапом.

## Review и проверки

Проверены CR API v1 по versioned Strimzi example, TLS без plain listener, отсутствие
secrets в Git, exact topic/group ACL и сохранение logical consumer identity.
Обнаружен риск ожидания Ready сразу после delete Pod: новый объект мог ещё не
появиться. Итоговый gate сначала ждёт create, затем Ready и сравнивает UID.
Добавлен отказ remote Docker до создания cluster, временный kubeconfig удаляется
даже при неудачном cleanup kind. Gates не трогают application namespace/БД.

Первый `pnpm kafka:gate` — exit 0: mTLS publish/read, общий key/partition, версии
1→2 после restart broker и cleanup. Итоговый повтор с ACL denials завершился exit 0.
Tools в /tmp проверены SHA-256 официальных поставщиков; kind0.33.0/kubectl1.37.0/
Helm3.22.0 фактически запущены. `node --check scripts/kafka-gate.cjs` — exit 0.
Логи: /tmp/wms501-gate.log, /tmp/wms501-final.log, /tmp/wms501-check-pr.log.

Промежуточный расширенный gate завершился exit 1 после restart; первая диагностика
не различала подшаги kubectl exec. Добавлены phase labels без credentials.
Административный kafka-topics describe заменён consumer-доступной проверкой offsets
трёх partitions; права consumer не расширены ради smoke. Итоговый повтор обязателен.

Следующий прогон подтвердил повторный read и три partitions, но негативный producer
probe завершился ошибкой проверки ожидаемого exception. В нём явно выключена
idempotence: consumer не имеет cluster IdempotentWrite, поэтому для проверки именно
topic Write нельзя полагаться на ранний InitProducerId. Это изменение probe, не ACL.
В диагностике допускаются только whitelisted authorization codes, не client config.
Повторная команда остаётся `pnpm kafka:gate`; результат до её exit 0 не принимается.

## Итоговые результаты

- `PATH=/tmp/wms501-tools:$PATH pnpm kafka:gate`: exit 0 на окончательном script,
  mTLS publish/read; две версии с одним UUID key и одной partition; новый broker
  Pod UID; retained messages прочитаны после рестарта. Broker partition count=3.
- Consumer publish отклонён topic ACL; foreign-group отклонена group ACL.
- `DOCKER_HOST=tcp://example.invalid:2375 pnpm kafka:gate`: ожидаемый exit 1
  до создания ресурсов. Никакого remote deployment не выполнено.
- Никаких plaintext keys/passwords в Git или console log; client config создавался
  внутри временного Pod. Рабочие .env/DB/volumes не использовались.
- `pnpm check:pr`: exit 0, 631 backend tests / 49 suites, 41 web tests;
  210 backend и 22 web source baselines без регрессий.

Повторное review проверило finally cleanup, private kubeconfig, literal ACL,
неизменную logical identity и запрет repartition без mapping. Application publisher,
валидация Kafka envelope/Registry и бизнес-эффекты consumers остаются WMS-502–504.
CJS gate проверен реальным выполнением, не заявляет instrumented 100% coverage.
Single broker restart не доказывает HA, сохранность при потере kind node/disk или
возможность автоматического cutover. Операторский chart/resources находятся отдельно
от application release; uninstall приложения не удаляет Kafka.

Финальный review выполнен после исправления probes. Root entry point повторён на
окончательном script; source/config после успешных gates не менялись. Последняя
запись результатов меняет только документацию и проверяется formatter отдельно.
Docker ps -a по prefix wms501- после gate пуст: собственные kind nodes удалены.

Coverage общего gate: backend Jest/V8 statements/lines 90,84%, branches 94,58%,
functions 89,42%; web Vitest/V8 statements 59,06%, lines 64,11%, branches 72,34%,
functions 53,68%. Новый CJS/Kubernetes smoke не входит в TypeScript denominator:
его evidence — настоящий Kafka gate, а не обещание 100% child-process coverage.
Эвикция данных за семь дней, rotation сертификатов, длительный soak, disk loss,
HA и application Kafka cutover не проверялись. Registry/AsyncAPI — следующий WMS-502.
