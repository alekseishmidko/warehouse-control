# WMS-502: Kafka contracts, Registry и выпуск schemas

## Вход и границы

Оператор выпускает schemas из Git, без включения producer. Source — прежние пять
JSON Schema 2020-12 и examples; runtime consumer остаётся EventContracts/Ajv2020.
Outbox/eventId, бизнес-правила, транзакции, handlers и wire JSON не менялись.
Успех — reproducible Registry spike, Git→Registry exact publication/diff, отказ
breaking candidate до POST и consumers-first runbook. Auth/warehouse ACL не заменяются Registry.

## Главное ограничение spike

Apicurio3.3.4 с digest из compose хранит исходные schemas, но native compatibility
не распознаёт 2020-12: даже description-only revision при FULL_TRANSITIVE возвращает
HTTP422 UnprocessableSchemaException, `could not determine version`.
Дополнительный probe показал, что VALIDITY=FULL принимает schema с `type:not-a-type`
(HTTP200). Поэтому server rules **не считаются strict2020-12 validation/compatibility**.

Выбранная dev-модель: Registry — catalogue; строгую validity выполняет local Ajv2020,
FULL_TRANSITIVE release policy — fail-closed local checker по всем revisions до POST.
Server COMPATIBILITY=NONE / VALIDITY=FULL зафиксированы как config, не как security proof.
Понижения dialect, выключения consumer validation или обещания native enforcement нет.
Raw privileged REST writer может обойти release CLI. Перед внешним стендом нужны
writer permissions только pipeline либо Registry с проверенной native поддержкой.
[ADR-0033](../adr/0033-schema-registry-contract-release.md) фиксирует это решение.

Topic определяется aggregateType, не schema major/event type. Receipt→receiving,
putaway-task→inventory.putaway, order-changed/shipping-changed→общий order topic,
picking-task→picking. Key остаётся aggregateId lowercase UTF-8 UUID, logical/group
inventory.putaway сохраняется. AsyncAPI описывает четыре streams, но WMS-501 provisioned
только receipt; остальные topics/ACL обязательны перед publisher WMS-503.

Новые typed optional fields к open schema не автоматически совместимы: старый schema
допускал произвольное значение такого extension. Checker допускает annotations и
unconstrained optional extension, замораживает validation constraints. Ref/unevaluated
semantics вне доказанного поднабора отклоняется fail closed; это консервативное
достаточное условие FULL, не общий JSON Schema subsumption solver.

## Review → refactor → повторное review

Разделены pure Git/topology/compatibility, общая Ajv factory, AsyncAPI check, REST
adapter, profile lifecycle и integration gate. Public verify/publish вместо boolean
write flag явно показывают эффект. Routing задан один раз на aggregate, поэтому два
order event types не расходятся по topics. Rules повторно используются из одной
константы; schema validity проверяется и в CLI, и непосредственно в adapter до HTTP.

Устранены пробелы первоначального spike: первая revision не публикуется до установки
rules; проверяются artifact type, latest equality, полная сохранённая история;
при invalid metadata/rule drift публикация блокируется. Не включали server deletion
API ради теста: probe artifacts живут только в disposable project и удаляются вместе
с контейнером. Source schema/generator output вручную не менялись.

Native tests покрывают breaking type/required/bounds/removal, unsafe typed extension,
false schema, closed/unevaluated/ref semantics, AsyncAPI2020-12 plugin и invalid payload,
remote endpoint/port/daemon rejection и adapter metaschema preflight до network.
Live gate дополнительно проверяет настоящую consumer библиотеку: UUID/date/quantity
coercion/conditional shipmentId/unknown version; additive поле сохраняется старым consumer.
Breaking candidate валиден по новой schema и fixture, но отвергается history guard;
число versions до/после отказа одинаково. Latest-only annotation drift и rule drift
проверены отдельным artifact, чтобы не спутать их со structural rejection.

На повторном review проверены Git base/argv без shell interpolation, loopback-only
HTTP/no redirects/deadlines, отсутствие runtime REST внутри transaction, private
Compose project без .env, cleanup и отсутствие credentials в diagnostics. Новых
подтверждённых дефектов в этих путях не осталось. Это не production security/HA proof.

## Ограничения и следующая работа

In-memory catalogue не восстанавливает historical revisions сам: production требует
persistence/auth/backup и accepted history. Release сериализует оператор; нет all-artifacts
transaction или гарантии защиты от privileged direct writer. Publisher/SDK consumer,
offset/rebalance/quarantine/cutover остаются WMS-503–506. Runtime не зависит от доступности
Registry при commit. CJS/tools tests не входят в TS coverage denominator; instrumented
100% child-process coverage не заявляется. Retention/HA/production rollout здесь не проверялись.

Источники: [Apicurio artifact dialect support](https://www.apicur.io/registry/docs/apicurio-registry/3.1.x/getting-started/assembly-artifact-reference.html),
[Docker profile](https://www.apicur.io/registry/getting-started/),
[Registry rule model](https://www.apicur.io/registry/docs/apicurio-registry/3.4.x/getting-started/assembly-registry-compatibility-modes.html).
Заявленная artifact support не заменяет описанные выше реальные native probe results.

## Заключительный прогон

После последних изменений строго последовательно выполнены root registry:up,
registry:publish/check/repeat/down, затем registry:gate и check:pr. Все exit0;
post-drift check внутри gate намеренно exit1 и подтверждён как ожидаемый refusal,
а не скрытый успешный release. Native tests6/6 входят в общий gate.

Backend Jest/V8: statements/lines90,88%, branches94,64%, functions89,46%.
Web Vitest/V8: statements59,48%, lines64,47%, branches73,13%, functions53,90%.
Не заявляется 100% project/business coverage; browser evidence не входит в Vitest.
Full CJS child-process coverage отдельно не инструментирована; evidence — native
regressions и реальные root commands. SQL/outbox/auth/lifecycle проверены существующими
integration/Docker suites. Внешний CI/deployment не выполнялся.

После exit0 source/config не менялись: записаны только результаты и статусы, formatter
и diff check выполняются отдельно. Docker image-check/gate также завершились exit0;
Registry Compose final state и pinned image не менялись после них. Исторические
artifact probes и in-memory test catalog удаляются при scoped Compose down.
