# WMS-111: локальная диагностика и адресный retry

Реализация завершена 2026-10-28, начата 2026-10-27. CLI работает только в локальном
explicit dev/test режиме с opt-in и DB admin membership. Production identity/remote admin API нет.

| Шаг   | Результат                                                                                                              |
| ----- | ---------------------------------------------------------------------------------------------------------------------- |
| 111.1 | Общий pure shared diagnostic snapshot, worker post-commit JSON eventId/correlationId/stream/consumer/attempt/lastError |
| 111.2 | Inspect CLI: delivery/leases/cursors/marker/history, optional validated preview 10 lines без unknown fields/token      |
| 111.3 | Retry по eventId+consumer, mandatory operator/reason, atomic audit/recovery record, total attempts/eventId сохраняются |
| 111.4 | NOWAIT locks, отказ active lease/processing/marker/predecessor bypass, monotonic counter и admin-only budget base      |
| 111.5 | Local signal dead/backlog/blocked/expired/age, configurable limits, Node exit 0/2/1 без внешних каналов                |
| 111.6 | Реальная последовательность compiled CLI после воспроизводимого production handler failure в disposable PostgreSQL     |

## Проверено

- `pnpm outbox:recovery-check`: проверенная root команда, настоящий CLI inspect/signal/retry,
  PostgreSQL и production putaway handler, без мутации dev volume или parent env.
- Финальный `pnpm --filter @warehouse/backend test:prepare` и
  `pnpm --filter @warehouse/backend exec jest --runInBand --silent`: **363 tests, 23 suites passed**,
  168 unit и 195 integration. Silent подавляет вывод console reporter, не проверки/ошибки.
- Test prepare проверяет contracts generation diff, production build, OpenAPI diff и compilation tests.
- `pnpm typecheck` прошёл, `pnpm db:generate` сообщил no schema changes.
- Все 17 новых файлов внесены в каталог, ссылки/Markdown и git diff --check корректны;
  после integration прогона disposable containers отсутствуют.
- Новые migrations 0016/0017 применены к чистым PostgreSQL 17 suites, прежние SQL не менялись.
- Dedicated role test: warehouse_app denied, warehouse_outbox_admin успешно retry без grants domain tables.
- AFTER faults audit/history/delivery/stream rollback-ят intervention полностью. Проверены два оператора,
  active row locks/leases, marker/cursor denial, exhausted budget и int4 attempt bound.
- Unknown payload extensions/invalid envelope/error strings не отражаются в CLI, credentials URL не печатается.
  TTL/удаление/изменение event или reset attempts/markers/cursors не применяются.

В verified drill: posted receipt stock=10/movement=1 → injected permanent DB fault после task
INSERT → dead/attempt=1 → inspect и signal alert → причина устранена → CLI retry с actor/reason
→ claim attempt=2 → одна task/marker/event, прежний stock=10, сигнал ok и immutable recovery history.
Повтор после maxAttempts начинает новый budget от total attempts, не обнуляя счётчик.

Первый общий прогон получил timeout старой nested Testcontainers lifecycle suite. Остальные
360 tests прошли; отдельный lifecycle повтор (2 tests) прошёл без увеличения timeouts. Финальные
общие прогоны завершились успешно: 362 tests, затем 363 после per-claim failure logging case. Skip/fallback Docker не добавлялись.
Ранний inspect test обнаружил raw Drizzle timestamp strings; adapter теперь явно нормализует их
в ISO UTC. Изменение проверено реальными CLI/DB tests, а не только mock formatter.

## Документация и практические ограничения

[Runbook с реальными командами](../runbooks/event-recovery.md),
[подробный флоу и пять Mermaid-схем](../flows/outbox-recovery.md),
[ADR-0017](../adr/0017-local-outbox-recovery.md),
[outbox module](../../apps/backend/src/infrastructure/outbox/README.md),
[shared diagnostics](../../apps/backend/src/shared/diagnostics/README.md).

Operator UUID — утверждение локального вызывающего, не authenticated directory identity.
DB credentials/provisioning вне migrations; dev owner остаётся superuser. CLI local guard не
доказывает локальность tunnel, DBA может обойти SQL guards. Existing trusted worker UPDATE
grants не считаются защитой от malicious raw SQL. Новая admin group не получает domain writes.

Inspect advisory: отдельные read-committed statements не дают repeatable snapshot history.
Локальные NDJSON и signal не заменяют Pino/Loki/metrics/remote alerts WMS-401/402. Replay/rebuild,
mass retry, external notifications, production admin endpoint и исправление corrupted facts отсутствуют.
Dev Compose не мигрировался/не перезапускался; локально применить pnpm db:migrate. Следующий этап WMS-112.

## Дополнение: русские комментарии и полнота документации

Документация WMS-111 дополнена картой файлов, таблицей безопасных отказов и действиями
оператора в [подробном флоу](../flows/outbox-recovery.md#карта-реализации-и-чтение-кода-wms-111).
Уточнено, что inspect читает состояние и историю разными запросами и не предоставляет
согласованный снимок всей команды. Ошибка stdout/закрытия после commit не означает rollback.

В коде по-русски описаны источник и доверие входу, результат/ошибки, роль БД, NOWAIT,
два курсора, предел int4, общий attempts и новый бюджет, атомарность аудита/истории/retry,
безопасный preview и фильтрация диагностики. В тестах пояснены AFTER-trigger fault,
удерживаемая блокировка, гонка операторов, локальная смена роли и тестовый stop-барьер.
Cleanup recovery history объяснён вместе с FK-графом. Применённые миграции не менялись:
русское описание SQL-ограничений дополнено в [drizzle README](../../apps/backend/drizzle/README.md#wms-111).

Проверка этого дополнения: typecheck, build/contract/OpenAPI diff через test:prepare,
**168 unit tests / 11 suites**, Node syntax checks обоих Docker-скриптов и локальные
Markdown-ссылки/ограждения — успешно. Сравнение 30 исходных/конфигурационных/generated
файлов с копией до правок подтвердило: TS/CJS после удаления комментариев совпадает,
Docker/Compose инструкции совпадают, SQL/JSON migrations/generated не изменились.
Integration/Docker suites в этом дополнении повторно не запускались: поведение не менялось;
предыдущие реальные проверки описаны выше и в отчёте WMS-112.
