## Gate 2: наблюдаемый результат

1. Supervisor входит через настоящий login/HttpOnly cookie. Чужой склад не появляется.
2. UI создаёт приёмку 10 штук настоящим двойным кликом. Barrier удерживает ответ;
   проверено, что кнопка заблокирована и отправлен только один POST. Тест получает
   HTTP response после реального commit
   через route.fetch, затем теряет ответ для браузера. Это fault injection сети,
   а не подмена SQL-эффекта.
3. Reload той же вкладки сохраняет исходную команду. Человек выбирает исходный склад
   и явно повторяет с прежним key/body. В БД остаётся один receipt; saved response
   возвращает тот же документ. Затем UI проводит приёмку.
4. До worker нет PutawayTask. Тест запускает production claim/process; UI обновляется
   и размещает 10 из receiving в storage. Worker stock не начисляет.
5. Заказ на 3 подтверждается, резервируется и собирается в shipping. UI сначала
   создаёт/отменяет draft shipment на 1, затем создаёт shipment на 3 и проводит его.
6. UI показывает storage=7, reserved=0, available=7. SQL подтверждает общий onHand=7,
   reserved=SUM(active)=0. Сохранён `apps/web/test-results/gate2-stock.png`, изображение
   просмотрено. Это ignored локальный артефакт, не source файл.
7. Дополнительный заказ на 4: partial pick 2 с нехваткой, partial shipment 1,
   cancel_pending и подтверждённый полный возврат оставшейся 1 из shipping в storage.
   Получен closed_mixed. Итог после дополнительной отгрузки: onHand=6, reserved=0;
   signed movements=6, active allocations=0. Уже отгруженное не возвращалось.
8. Ещё один заказ на 2 резервируется явно на 1, release освобождает 1, заказ отменяется.
   Остаток не меняется. История показывает movements и shipment audit.
9. Tab/Enter переводят фокус по skip link в main. После logout viewer входит через
   настоящий login и получает 403 при попытке приёмки. Число receipts не меняется.

UI все изменения выполняет через HTTP. SQL в gate читает доказательства; production
fixtures создают исходные справочники и синтетические учётные записи. Worker запускается
из теста для детерминированного наблюдения eventual шага. Ошибки страницы проверяются;
browser/Vite/API/worker/pool/container закрываются с ограниченными deadlines.

## Ограничения

Это локальный SPA и dev proxy. Production serving, TLS gateway, web Docker image,
Kubernetes и внешний CI/CD ещё не настроены. Рабочая .env/БД не менялись, внешний
deployment не выполнялся. Новых migrations нет: read справочники используют PK.

Журнал sessionStorage переживает reload, но теряется при закрытии вкладки. Он не
блокирует другие вкладки. Отозванное право может запретить replay неизвестной команды;
ключ остаётся для разбора. Автоматического replay и отдельного result-status API нет.
Нет UI управления пользователями/справочниками и произвольных stock adjustments.

Проверены Chromium и базовая клавиатурная доступность; Safari/Firefox, screen reader,
полный WCAG audit и реальные мобильные устройства не проверялись. Физическое действие
подтверждает оператор. Итоги остатков относятся к загруженным строкам. Read pages
не обещают snapshot между запросами; task появляется после commit worker.

Повтор после frozen install однажды остановился на setup двух PostgreSQL suites:
Harness не подготовил БД; точная причина по безопасной ошибке не установлена.
37 suites прошли. Тесты не пропущены, timeouts не
увеличены. Docker API проверен, оставшихся контейнеров этого прогона нет. Обе suites
(outbox-recovery и directory-reads, 16 tests) отдельно повторены успешно без изменения
production code, миграций или harness. Итоговый полный check:pr повторён успешно: exit 0, 39 Jest suites / 576 tests,
4 Vitest files / 35 tests, 9 quality self-tests, Chromium gate 2 и оба coverage guard.

Recovery guard формы проверен изолированным mutation probe: временно удалены две
защиты submitted (начальное восстановление из журнала и сохранение после uncertain).
Оба целевых regression tests упали; исходный файл восстановлен в finally. После
восстановления все 35 Vitest tests прошли. Это проверка полезности tests, не отключение
production guard и не пропуск integration.
