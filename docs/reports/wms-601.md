# WMS-601: полный локальный pipeline и сквозное review

## Требования до изменений и границы

Пользователь поручил WMS-601.1–5, review всего приложения, JSDoc, рефакторинг и проверку
всего кода. [Source task](../tasks/wms-601.json) оформлен до реализации guards.
Вход — source files, pinned Git checkpoint, manifests/lockfile, schema contracts и
локальные инструменты. Участник — разработчик/агент с правом изменить checkout и
запустить disposable тесты. Внешний hosting, публикация images и GitOps не входят.

Успех — source-bound pipeline выполняет frozen install и обязательные gates,
нарушения contracts/docs/migrations дают nonzero, saved HTTP result сохраняет wire type,
прежний API/worker совместим с candidate schema в проверенном сценарии. Ошибки tools,
Docker/registry/Chromium/Helm, неправильная база и неполные результаты запрещают ready.
Секреты, рабочая .env, dev volumes и внешний deployment не меняются.

Инварианты warehouse/transactions/auth/outbox не меняются. Readiness не является
бизнес-приёмкой. Начальный baseline — dev checkpoint WMS-506
`e79cb2fddf3125894decb0b9ef20988726732d45`: release tags отсутствуют; пользователь явно согласовал checkpoint WMS-506
как исходный dev-baseline для WMS-601.3.
Это не утверждение о существовании production release. Детали исполнения:
[flow и Mermaid](../flows/pr-pipeline.md), [guards](../../scripts/pr-checks/README.md).

## Сквозное review приложения

Review не ограничивалось diff. Автоматический inventory охватывает собственные
backend/web/scripts/infra/docs файлы, generated имеет владельца. Typed lint/typecheck,
architecture AST graph и file/public-doc checks применяются ко всему соответствующему
source набору, а не только новым файлам. Смысловой review выполнен по подсистемам:

| Область                        | Проверенные вопросы и ключевые пути                                                                                                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend HTTP/identity          | AuthGuard default deny, server actor, CSRF/Origin, session validity после lock wait, ACL до replay; SessionsService/AuthService/AccessService и controllers                                  |
| Общие транзакции/serialization | PostgresTransactionRunner capability scope/nested guard/COMMIT logs, canonical JSON type/depth/size, HttpCommandsService claim/result и await boundary                                       |
| Warehouse business             | ReceivingService post; inventory reserve/pick/ship; fulfillment PickingService/ShippingService; общий order/context, qty, partial pick/ship и B3 full staged return                          |
| Worker/Kafka                   | ApplicationConsumerService retained identity/marker/cursor; WorkerService claim/process/failure; KafkaMessageService ownership/offset-after-commit, publisher singleton и durable quarantine |
| Web                            | ApiClient session epoch/uncertain result, SessionProvider login/logout ordering, WorkspaceProvider warehouse scope, CommandJournal recovery без credentials; generated API boundary          |
| Infrastructure/scripts         | Compose/Helm/runtime Secret refs, probes/rollout и migrations; harness locks/content evidence; schema generator/release guard; Docker/Kafka/kind gate entrypoints                            |
| Tests/documentation            | Реальные SQL/locks/fault suites, typed fixtures, coverage ratchets, README/flow/JSDoc/catalog consistency                                                                                    |

Это обзор всех подсистем с углублением в перечисленные критические пути, не заявление
о ручном построчном прочтении каждого generated/test/schema файла или об отсутствии
всех уязвимостей. Автоматическая syntax/docs проверка тоже не заменяет смысловой review.

## Findings, воспроизведение, исправления

**R601-01, P2, HttpCommandsService saved headers.** Server-owned `location` мог оказаться
массивом вместо строки. `RegExp.test` приводил массив с одним relative URL к строке,
после чего callback effect и неверный HTTP result коммитились. Это нарушение runtime
wire contract, не доказанный обход auth или возможность клиента назначить headers.
Новый PostgreSQL test `601 invalid Location rolls back effect and saved result`
на старом коде получил fulfilled result с array Location вместо expected rejection.
После `typeof location === 'string'` test проходит, обе таблицы остаются пустыми.
Матрица также проверяет финальные LF/CR/U+2028/U+2029: absolute end guard
не принимает позицию перед последним line terminator, которую допускает JS `$`.

Refactor: pure snapshot/validation вынесен в private prepareSavedResult. Execute
теперь описывает orchestration: authorization → claim/replay → work → validate/save →
commit. Canonical snapshot, статусы/keys/headers allowlist и owner commit сохранены.
JSDoc объясняет причину type guard, server error classification, borrowed transaction
и отсутствие I/O в pure helper. Нового слоя/shared abstraction не добавлено.

**R601-02, P2, release gates.** Прежний schema check по HEAD не сравнивал всю историю
после checkpoint, а OpenAPI breaking comparison отсутствовал. Native regression
коммитит breaking change после baseline и доказывает отказ нового guard/runner.
Проверяется весь retained schema set, включая удаление, migration prefix и topology.
Новые API endpoints допускаются; arbitrary existing shape evolution fail closed.

**R601-03, P3, database-types link.** Anchor identity Schemas не совпадал с heading,
содержащим тире. Ссылка исправлена и проверяется новым local-anchor gate. Первоначальный
наивный поиск подстроки давал ложные missing catalog для relative Markdown links;
исправлен parser, существующие корректные catalog entries не переписывались.

Review новых guards: имена JSON properties/map keys description/title не удаляются
как annotations; const/enum/default остаются данными. Static documentation checker
не читает source symlinks наружу checkout. Shared Git source inventory выделен для
двух реальных потребителей. Native runner fixtures обновлены под mandatory install/
image steps; тестовый noop не используется в рабочем pipeline.

Повторное review подтвердило сохранение auth/warehouse ACL, inventory ownership,
transaction/outbox atomicity, stable names/cursors и отсутствие raw credentials в
новых outputs. Новых подтверждённых дефектов в просмотренной области после исправлений
не выявлено. Содержательные комментарии уже были в большинстве source; blanket
комментарии, пересказывающие синтаксис, не добавлялись.

Во время разработки выполнены:

```sh
pnpm harness:plan docs/tasks/wms-601.json
node --test scripts/pr-checks/checks.test.cjs scripts/harness/harness.test.cjs
pnpm --filter @warehouse/backend typecheck
pnpm lint
pnpm test:integration --runInBand --runTestsByPath .test-dist/test/integration/http-commands.spec.js .test-dist/test/integration/release-migrations.spec.js
```

Native protocol/negative tests прошли12tests (8harness и4guards). Targeted integration первоначально
показала отказ regression на старом коде (1 failed/22 passed); после исправления —
23passed/2suites, после расширения Location matrix —27passed/2suites, включая реальный baseline upgrade. Typecheck/lint прошли.
Helm3.22.0 загружен с get.helm.sh, SHA256 сверён с published checksum. Временный tool
находится в ignored artifacts/tools; WMS_HELM явно передаётся pipeline/readiness.

Финальный процесс:

```sh
pnpm pr:pipeline docs/tasks/wms-601.json
pnpm harness:ready docs/tasks/wms-601.json
```

Результат финального run берётся только из `artifacts/harness/wms-601/latest.json`
и private logs; source report не переписывается после run, чтобы evidence не стало stale.
Run UUID/snapshot/results публикуются в итоговом ответе. До passed current readiness
этап не считается технически проверенным, даже при успешных отдельных commands.

Ни один coverage baseline не снижен. Общего100% coverage приложения не заявляем;
child-process old runtime coverage не объединено с parent V8. Structural docs gate
проверяет наличие, смысл остаётся review. External link uptime не проверяется.
API diff — консервативное достаточное условие, не полная спецификационная эквивалентность.
Upgrade suite проверяет critical receipt/task/marker path; произвольная будущая DDL
требует targeted migration/rollback/expand-contract tests. Старые dependencies требуют
доступного cache/registry и остаются отдельным воспроизводимым release build.

Внешний CI hosting, Actions/GHCR credentials, image scanning/release publication,
Argo CD, encrypted GitOps secrets и external release/restore drill — WMS-602–604,
в этом изменении не реализованы. Рабочий стенд и volumes не менялись.

### Проверка install watcher

Первый полный pipeline остановился STALE после успешного frozen install. Сравнение
manifest hashes подтвердило одинаковые source bytes. Дополнительный fs.watch probe
показал pnpm `_tmp_<pid>_<32hex>` и macOS root-directory notification.
Watcher теперь игнорирует только исчезающий неизвестный install probe и уведомление
самого каталога. Известные inputs проверяются до исключения; persistent probe меняет
финальный snapshot. В других gates такой temp write по-прежнему STALE.
Native regression проверяет transient/persistent probe, source write/revert во время
install и тот же probe в обычном PR gate. Это не отключение input watcher или
разрешение изменять lockfile. Финальный pipeline повторяется на новом snapshot.

### Проверка CI lint probes

После install следующий полный run остановился на test:quality. Оба прежних
ESLint lintText self-tests возвращали0rules при CI=true и проходили без CI.
Проверка установленного parser показала immutable single-run Program, использующий
disk AST для первого виртуального input. Self-test factory теперь задаёт
disallowAutomaticSingleRunInference=true только для lintText probes. Правила и
production CLI mode не менялись; ожидания no-floating-promises/no-explicit-any/
ban-ts-comment и no-restricted-imports сохранены. Параметр описан в
[официальной документации parser](https://typescript-eslint.io/packages/parser/#disallowautomaticsingleruninference).
TSESTREE_* включён в environment fingerprint. Runtime зависимости не менялись,
упрощения guards/skip нет. Полный pipeline повторяется с CI=true.
