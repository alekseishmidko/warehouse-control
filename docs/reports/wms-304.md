# WMS-304: lifecycle и rollout

## Контракт до реализации

Вход: SIGTERM/SIGINT процесса и kubelet HTTP probes. Probes публичны, не выдают
конфигурацию/credentials и не предоставляют бизнес-доступ. Actor/ACL/CSRF складских
команд сохраняются. Успех команды определяется commit вместе с saved HTTP result;
потерянный ответ восстанавливается только исходным key. Shutdown не выполняет retry.

| AC        | Ожидаемый результат                                                        | Проверка                              |
| --------- | -------------------------------------------------------------------------- | ------------------------------------- |
| AC-304-01 | Startup/liveness/readiness разделены; DB outage не ломает liveness         | HTTP tests + Kubernetes outage        |
| AC-304-02 | Signal запрещает новые запросы/claims, активная операция ограничена        | Process tests + реальные Pod deletion |
| AC-304-03 | Grace превышает timeout операции/drain; API/worker обновляются с surge     | Helm render + rollout                 |
| AC-304-04 | Kill до commit откатывает эффект; kill после commit не дублирует результат | PostgreSQL/Pod barriers и replay      |
| AC-304-05 | v1 event и additive migration совместимы с работающим прежним процессом    | Clean kind Gate 3 + UI flow           |

Критерии подтверждаются матрицей реализации и фактическими проверками ниже.
Проверки выполнены 2026-11-09 (Asia/Bangkok).
Single-node PostgreSQL не является HA. Внешние storage/backup/restore/secrets требуют
отдельного решения перед внешним стендом. Рабочие .env/dev volumes не используются.

## Ревью, исправления и повторное ревью

- R-01 исправлен: target expression SELECT FOR UPDATE больше не используется как
  проверка часов после ожидания. Постоянный regression ждёт настоящий DB lock,
  expiry по DB clock и commit blocker без изменения tuple; ожидает null/no marker.
  До исправления production reproducer возвращал ненулевой claim (предыдущий review).
- Ревью API shutdown обнаружило late bind: signal во время app.init не отменяет
  уже начатый app.listen. Init отделён от listen; stop проверяется повторно после await.
  Regression с настоящим асинхронным Nest OnModuleInit падал на прежнем dist: listener
  открывался после signal. На исправленном коде listener не открывается.
- Ошибка cleanup не доказывает освобождение ресурсов. API/worker сохраняют deadline
  при rejected close. Worker закрывает pool в finally даже при ошибке probe listener.
  Regression на прежнем dist показывал отсутствие hard deadline после rejected close.
- Dev supervisor раньше рассчитывал окно только из worker deadline. Теперь выбирает
  max(API20s, worker15s)+5s=25s. Реальный pnpm dev:all проверяется после остановки watch
  перед check:pr; рабочие данные не затрагиваются.
- Gateway setup ранее начинал auth POST, пока старый Pod ещё terminating. Добавлены
  ожидание завершения setup rollout и безопасный GET, проверяющий реальный API route.
  API preStop5s даёт время EndpointSlice/NGF убрать upstream до SIGTERM. После DB outage
  gate также ждёт возвращения маршрута; складские POST автоматически не повторяются.
- Обновлён точный список routes в OpenAPI regression и generated artifacts через
  штатные генераторы. Новые probes описывают200/503 и сохраняют закрытость warehouse routes.
- Admission middleware сохраняет стандартный Problem contract через общий renderer
  ProblemFilter.respond. Regression на прежнем dist получал application/json вместо
  application/problem+json; после исправления проверяет503, correlationId/header,
  instance и отсутствие idempotency claim. Формат controller errors не менялся.
- При ревью тестовых путей обнаружена коллизия имени lifecycle.spec. Исходные два
  harness cleanup/isolation tests восстановлены без изменений; новые API tests имеют
  отдельный api-lifecycle.spec. Финальный полный suite обязан включать оба файла.

Повторное ревью охватывает source, тестовые hooks, итоговые Helm resources,
доверие к probe input, leases, transaction ownership, stdout/Secrets и cleanup.
SQL/advisory barriers, IPC и test DDL отсутствуют в production handlers.
R-05 (deadlock return/reserve разных заказов), R-06 (исторический владелец бизнес-правил)
и прежний R-04 по dev dependencies этим этапом не исправлялись. Позднее они исправлены
[отдельным изменением](review-fixes-r04-r06.md); остаточный registry advisory deepmerge указан явно.

## Coverage и ограничения

Существующие202 per-file baseline не снижаются. Два новых lifecycle файла получают
reviewed baseline после parent unit и real child tests. Итог backend:90.62%
lines/statements,94.54% branches,89.84% functions; web:62.20% lines,57.77%
statements,72.36% branches,52.81% functions. Оба baseline gate прошли. Первоначальная цифра100%
branches для неисполненного api-process с нулём найденных ветвей не является
доказательством покрытия; baseline нового файла устанавливается по фактическому
исполнению. Child process и Kubernetes evidence не прибавляются к Jest/V8 автоматически.
У api-process100% lines/statements,91.66% branches и66.66% functions по parent V8:
не исполняется пустой initializer wake; type guard чужого HTTP adapter и ошибка
callback server.close отдельно не инъецировались. Startup/drain/deadline/rejected
app.close проверены наблюдаемыми результатами, включая настоящий listener и child.
ProcessHealth имеет100% lines/statements/functions и96.42% branches; fallback
отсутствующего request.url не моделируется искусственным HTTP объектом.
Hard process exit намеренно наблюдается через mock process.exit в unit; реальные
SIGKILL/rollback и worker hard deadline подтверждаются отдельными child/Pod tests.
Не заявляется100% business branches всего проекта или отсутствие всех crash interleavings.

Single-node kind и PostgreSQL replicas1 не являются HA. PVC не заменяет backup.
Перед внешним стендом отдельно определить storage/reclaim, backup/restore drill,
Secret encryption/rotation и TLS trust. Публикация или внешний deploy не выполнялись.
Рабочая.env и dev volumes сохранены. Подробный владелец поведения —
[lifecycle flow](../flows/lifecycle.md), [ADR-0029](../adr/0029-process-lifecycle.md).
